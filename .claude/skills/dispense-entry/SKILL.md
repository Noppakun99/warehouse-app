**⛔ อ่านรูปใบเบิกฟอร์มพิมพ์รายการ (น้ำเกลือ / ถุง-ขวด-ตลับ) — ฝั่งขวา (หน่วยนับ+จำนวนที่เบิก) อาจพิมพ์เลื่อนจากฝั่งซ้าย 1 บรรทัด** (15/10/2569 ลงผิด 2 ใบ: ER D-5-W 1000→100ml · ห้องยาG S010→S007 — ใบ ER ช่องหน่วยแรกอยู่ระดับหัวตาราง) → **ก่อนลงทุกใบ**: เทียบลำดับหน่วยนับฝั่งขวาในรูปกับฟอร์มเปล่า (`Desktop\ยอดคงคลัง\ฉบับเก่า\ใบเบิกเวชภัณฑ์น้ำเกลือ.pdf` / `ใบเบิกเวชภัณฑ์ยาและมิใช่ยา.pdf` / `ใบเบิกเวชภัณฑ์มิใช่ยาถุง.ขวด.ตลับ.pdf` — ฉบับเก่าที่ยังหมุนเวียน · ฉบับใหม่มีช่อง "ที่" ซ้ำ ไม่ต้องเทียบ) หา offset · ผูกตัวเลขผ่านหน่วยนับข้างตัวเลข ไม่ลากจากชื่อยา · เลื่อนแล้วเลื่อนทุกตัวในใบ · ตารางยืนยันกับ user แสดงหน่วยข้างตัวเลข + offset ทุกรายการ (memory `handwritten-requisition-to-excel`) · **ใบเบิกฟอร์มรายการที่ไม่ใช่ฉบับปัจจุบัน** (ไม่มีบรรทัด "ฉบับปรับปรุง" ท้ายใบ หรือฉบับเก่ากว่า `REVISION` ใน [printedReqForm.js](src/lib/printedReqForm.js)) → ลงตามปกติ แล้ว**เตือน user ให้ส่งฉบับล่าสุดกลับไปกับของ** + จดในหมายเหตุทะเบียนใบเบิก (ตกลง 16/10/2569)

**PDF ใบเบิกทุกใบ (ทุกหน่วยงาน) ทำด้วย `scripts/dispense-pdf.ps1` — หัวกระดาษกลางขึ้น "เลขที่ <เลขรับใบเบิก>" อัตโนมัติจากคอลัมน์ AD · ฟอร์มใหม่ 02/11/2569 ซ่อน MainLog+ชนิด เฉพาะใน PDF แล้วขยายหมายเหตุ 2 เท่า ชีทไม่เปลี่ยน · ตัวอักษรบนกระดาษ 10 พอยท์ (user ตกลง 05/11/2569 — ความกว้างคอลัมน์ตั้งในสคริปต์ ไม่อิงชีท) · DetailedLog 14 พอยท์ (user สั่ง 09/11/2569 — ความกว้างรวมต้องเท่าเดิม ไม่งั้น Excel ย่อทั้งหน้า)** (user สั่ง 12/10/2569 · ลงคอลัมน์ AD **ก่อน**ทำ PDF เสมอ · แถวในใบเลขต่างกัน = สคริปต์หยุด · ใบที่ไม่มีเลข เช่นก่อน 12/10/2569 = หัวกลางว่าง) · พารามิเตอร์ `-StockPath -LogPath -Out -Rows <แถว,…> -Sig "รหัส|lot|N|หน่วยงาน ; …" -Title [-SortLog]` · เปิดไฟล์อ่านอย่างเดียว · ไม่ทับไฟล์ที่มีอยู่

**ลงใบเบิกทุกแถว: เช็คคงเหลือจริงของ lot บนชั้น แล้วเขียนในหมายเหตุ Q ถ้า "คงเหลือหลังจ่าย" (O) ไม่ใช่ตัวเลขที่คนจัดยานับได้** (user สั่ง 14/10/2569 — คนจัดยาใช้นับยอดที่เหลือบนชั้นหลังหยิบ):
- O คิดจาก**แถว Master แถวเดียว**ที่ตัด → lot เดียวกันที่แยกหลายแถวใน Master (`ยกยอด`/`ยกยอด(2)`/ราคาต่าง/ชนิดรายการต่าง) O จะต่ำกว่าของจริง เช่น ขึ้น 0 ทั้งที่ lot ยังเหลือ → PDF ทำให้เข้าใจว่ายาหมด
- รวม U ของ Master ทุกแถว **รหัส+lot เดียวกัน** หลังตัด + คงคลังรวมทั้งรหัส แล้วเขียน: `lot <lot> ยังเหลือ <N> (แถว<ชนิดรายการ>) · คงคลังรวม <M>` · lot หมดแต่รหัสยังมี lot อื่น → `lot <lot> หมด · คงคลังรวม <M> (lot <…>)` · มีหมายเหตุอื่นอยู่แล้ว ต่อท้ายด้วย ` · `
- แถว Master ที่ยัง `รอตรวจรับ` (คอลัมน์ C) แยกบอก ห้ามนับรวมเป็นของจ่ายได้: `… · รอตรวจรับอีก <N> (บิล <…>)` · lot เดียวกันคนละที่เก็บ (D/E ต่าง เช่น Manidipine 260873 E-1-x กับห้องประชุมเล็กชั้น4) บอก**ยอดรวมทั้ง lot ก่อน** แล้วแจกที่เก็บ: `คงเหลือ lot <lot> = <รวม> <หน่วย> (ชั้น 1 <ที่เก็บ> = <a> + ห้องประชุมเล็กชั้น 4 = <b>)` (user สั่ง 27/10/2569 — แบบเดิม `อีก <N> ที่ <ที่เก็บ>` อ่านไม่รู้ว่า lot เหลือเท่าไหร่ · ตัวอย่างแถว 8723)
- **O ตรงกับยอดที่เหลือของ lot อยู่แล้ว = ไม่ต้องเขียน `lot ยังเหลือ N`** (user สั่ง 02/11/2569 — หมายเหตุยาวทำแถว PDF สูงเกิน)
- ทำ**ก่อน**ทำ PDF (หมายเหตุขึ้นใน PDF) · ตัวอย่างแรก: Sertraline 50mg แถว 8486 (บย.70/0005 ห้องยาG) O = 0 แต่ L695023 ยังเหลือ 108 ในแถว `ยกยอด(2)` — ใส่หมายเหตุย้อนหลัง 14/10 ไม่พิมพ์ใหม่

**ลงใบเบิกทุกแถว: exp ของ lot ที่จ่ายเหลือน้อยกว่า 7 เดือนนับจากวันที่เบิก ต้องเขียนในหมายเหตุ Q** ว่า `exp <วว/ดด/ปปปป> ใกล้หมดอายุ` (user สั่งเป็นกฎบังคับ 09/11/2569 · ทำก่อนทำ PDF · มีหมายเหตุอื่นต่อท้ายด้วย ` · ` · การตีความ "น้อยกว่า 7 เดือน" รอ user ยืนยัน)

**⛔ ก่อนจ่ายทุกใบ: เช็คว่าจ่ายแล้วคงเหลือพอให้หน่วยงานอื่นไหม (เทียบเรท) + ใกล้ exp ไหม** (user สั่ง 10/11/2569) · รัน `python -B .claude/skills/dispense-entry/scripts/rate_check.py --date <ISO วันเบิก> --lines "รหัส:จำนวน,…"` (อ่านอย่างเดียว · copy ไฟล์ไป temp เอง · หาคอลัมน์ชีท `วิเคราะห์สั่งซื้อ` จากหัวแถว 3) **ก่อน**ทำตารางยืนยันกับ user:
- จ่ายได้ = Σ U ทุก lot ของรหัส (ไม่นับแถว `รอตรวจรับ`) · หลังจ่ายพอใช้อีก (วัน) = หลังจ่าย ÷ Avg/วัน · เทียบ Lead Time · ดูของรอตรวจรับ + แถว ☐ ในรายงานการซื้อยา (แจ้งซื้อแล้วหรือยัง)
- **⛔ ถาม user ก่อนลง (ห้ามตัดยอดจ่ายเอง เสนอยอดแบ่งจ่ายพร้อมตัวเลข)**: ของไม่พอจ่าย · ใบเดียว ≥ 1 เดือนของเรท หรือ ≥ ครึ่งของที่จ่ายได้ · หลังจ่ายพอใช้ไม่ถึง Lead Time **และ** ไม่มีของรอตรวจรับ **และ** ยังไม่แจ้งซื้อ (ถามเรื่องแจ้งซื้อด่วนด้วย — memory `urgent-purchase-line-template`)
- **⚠ จ่ายตามขอได้ แต่บอก user ในสรุป**: พอใช้ไม่ถึง Lead Time แต่มีของรอตรวจรับหรือแจ้งซื้อแล้ว · **ต่ำกว่า ROP / สถานะ `สั่งเพิ่ม` อย่างเดียวไม่ใช่เหตุตัดจ่าย** (เป็นเรื่องแจ้งซื้อ ยาส่วนใหญ่อยู่ใต้ ROP)
- **exp**: คงเหลือใช้ไม่ทันก่อน exp ของ lot แรก (พอใช้อีก > จำนวนวันถึง exp) = จ่ายตามขอได้ ไม่ต้องกั๊ก · lot ที่จ่าย exp < 7 เดือน → หมายเหตุ Q ตามกฎข้างบน
- ตารางยืนยันกับ user ใส่ผลต่อรายการ: หลังจ่าย · พอใช้อีก (วัน) · LT · รอตรวจรับ/แจ้งซื้อ · ผล ✓/⚠/⛔ · ตัวอย่างแรก: วัดประยูร 9/11/69 (บย.70/0065) — Omeprazole หลังจ่ายพอใช้ 20 วัน < LT 24 แต่แจ้งซื้อแล้ว 02/10 · Glyceryl 60ml ใบเดียวขอครึ่งของที่จ่ายได้ (รอตรวจรับ 600) user ยืนยันจ่ายเต็ม
