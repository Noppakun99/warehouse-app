## ขั้นตอน

### 1. เช็คว่าไฟล์อัพเดตล่าสุดเมื่อไหร่ — verify: ต้องทำก่อนทุกครั้ง

```bash
ls -la --time-style=+%Y-%m-%d_%H:%M ~/OneDrive/ยอดคลังยา_69.xlsm ~/OneDrive/รับจากการซื้อ_ยืม_ตุลา2567-2569.xlsm ~/OneDrive/รายงานการซื้อยา_69.xlsx; date
```

**ไฟล์ถูกแก้ระหว่างวันบ่อยมาก** — เคยเจอสถานะเปลี่ยนจาก "รอตรวจรับ 6 รายการ" เป็น "ตรวจรับแล้วเกือบหมด" ภายใน 20 นาที **ห้ามตอบจากผลรอบก่อน ต้องรันใหม่เสมอ**

### 2. รันสคริปต์ — verify: ได้ตัวเลขออกมา ไม่ error

```bash
node .claude/skills/drug-shortfall-report/scripts/shortfall.cjs --from 14/09/2026
```

| flag | ความหมาย |
|------|----------|
| `--from DD/MM/YYYY` | วันเริ่มช่วงที่สนใจ (default 14/09/2026) |
| `--ward` | เฉพาะฉบับ 1 (หน่วยงาน) |
| `--drug` | เฉพาะฉบับ 2 (ตามยา) |
| ไม่ใส่ | ออกทั้ง 2 ฉบับ |

ถ้า path ต่างจาก default: ตั้ง `ONEDRIVE_DIR` / `XLSX_PATH` เป็น env var

### 3. อ่านผล + ตรวจส่วน "ข้อมูลขัดแย้ง" — verify: ต้องอ่านทุกครั้ง

สคริปต์เทียบ **เลข "จ่าย" ในหมายเหตุ vs ผลรวม `ปริมาณ (ออก)` จริงทุก lot** ถ้าไม่ตรงจะขึ้นท้ายรายงาน
- ผลรวมจริง **≥ จำนวนที่ขอ** → จ่ายครบแล้ว หมายเหตุเขียนตก → **สคริปต์ตัดออกให้แล้ว**
- ไม่ตรงแบบอื่น → **ต้องแจ้ง user ให้คลังตรวจสอบ อย่าเงียบ**

### 4. เขียนรายงาน + ข้อความไลน์ — verify: มีข้อความพร้อมคัดลอกเสมอ

ผู้ใช้เอาไปส่งกลุ่มไลน์ต่อ **ทุกครั้ง** — ปิดท้ายด้วยบล็อก ` ``` ` ที่คัดลอกส่งได้เลย จัดกลุ่มตามสถานะ (ดูล่าง) ระบุจำนวน + หน่วย + วันที่ ไม่ใช่แค่ "มา/ไม่มา"

คนถามอยากรู้ว่า **"คอขวดอยู่ที่ไหน"** ไม่ใช่แค่ "ขาดเท่าไหร่"

| 🔴 **บริษัทยังไม่ส่ง** | checkbox ☐ + ไม่มีบิล `การซื้อ` หลังวันแจ้งสั่ง | **ตามบริษัท** |

## กับดัก 6 ข้อ (เคยพลาดมาแล้วทุกข้อ)

### 1. ชีท `'เบิก '` มีช่องว่างท้ายชื่อ + header อยู่แถว 6
แถว 1-3 เป็นบล็อกค้นหาลอยอยู่ด้านบน — `sheet_to_json` แบบ default จะได้ key เพี้ยนทั้งชีท ต้อง `.slice(6)`

### 2. คอลัมน์ `จำนวนที่ขอ` แทบไม่มีคนกรอก
ก.ย.69 มีแค่ **2 แถวจาก 8,000+** — ข้อมูลจริงซ่อนใน **คอลัมน์ `หมายเหตุ` (index 16) เป็น free-text** รูปแบบ `เบิก 36 จ่าย 24 ยาหมดรอของส่ง แจ้งสั่งวันที่ 27/8/2026` ต้อง regex จับ

### 3. ยา 1 ตัวแตกหลาย lot = หลายแถว → ห้ามนับซ้ำ
group ด้วย `code|date|ward` แล้วบวก `ปริมาณ (ออก)` — **เคยรายงาน Furosemide ว่าขาด 14 ทั้งที่จ่ายครบ** เพราะหมายเหตุเขียน "มี 4 lot" แต่จริงมี 5 lot

### 4. `หน่วย` ไม่ใช่หน่วยนับเสมอ — ต้องดู `packsize` + ต้องมีหน่วยกำกับทุกตัวเลข
ถ้า `packsize = 1` หน่วยจริงคือ **`หน่วยย่อย`** เช่น Povidone-iodine หน่วยเขียน `450ml` แต่ `packsize=1, หน่วยย่อย=ขวด` → รายงานว่า **30 ขวด** ไม่ใช่ "30 450ml"
ถ้า `packsize > 1` หน่วยคือ**แพ็ค** ใช้ตามที่เขียน (`500เม็ด` = กล่องละ 500 เม็ด)
**ยาที่คลังหมดเกลี้ยงจะไม่มีแถวใน `Master` เลย** (ไม่เหลือ lot) → ต้อง fallback หน่วยจากคอลัมน์ `หน่วย` ของไฟล์รายงานซื้อยา ไม่งั้นหน่วยว่าง
> **เขียนว่า "คงเหลือ 4" เฉยๆ ไม่ได้** ต้อง "คงเหลือ 4 กล่อง (500เม็ด)" — คนอ่านต้องรู้ว่า 4 เม็ดหรือ 4 กล่อง

### 5. วันที่ในชีท `รับยา` ปนกัน 2 รูปแบบ
`m/d/yy` (`5/25/26` = 25 พ.ค.) ปนกับ `dd/mm/yyyy` (`16/9/2026` = 16 ก.ย.) — **ห้ามหยิบแถวท้ายไฟล์เป็น "ล่าสุด"** ต้อง normalize แล้ว sort ก่อน (เคยสรุปผิดว่า Charcoal ของมาแล้ว ทั้งที่มาล่าสุดเดือน 5)

### 6. checkbox ☐ ไม่ได้แปลว่าลืมติ๊ก — ต้องเช็ค `สถานะการซื้อ`
ของที่เข้ามาหลังวันสั่งอาจเป็น **ยืม / บริจาค / แลกเปลี่ยนยาหมดอายุ / ชดเชยสินค้า** ซึ่ง**ไม่ใช่ของที่สั่ง** → checkbox ☐ ถูกต้องแล้ว
นับเป็น "ของมาแล้ว" **เฉพาะ `สถานะการซื้อ = การซื้อ`** เท่านั้น
> ตรวจ 61 รายการเมื่อ 21/9/69: **ไม่มีตัวไหนลืมติ๊กเลย** ทั้ง 4 ตัวที่สงสัยเป็นยืม/แลกเปลี่ยนทั้งหมด — อย่ารีบกล่าวหาว่าไฟล์ผิด

## รูปแบบข้อความไลน์

**ฉบับ 1 — ส่งหน่วยงาน** (เน้น "จะได้ไหม")
```
ยาที่จ่ายไม่ครบ <หน่วยงาน> (เบิก <วันที่>)

รับได้เลย — ของพร้อมจ่าย
1. <ยา> — มี <n> <หน่วย>

รอตรวจรับ จะได้ภายใน 1-2 วัน
2. <ยา> — ของถึงแล้ว <n> <หน่วย>

ยังไม่ได้ บริษัทยังไม่ส่ง
3. <ยา> — ขาด <n> (สั่ง <วันที่> ค้าง <n> วัน)
```

**ฉบับ 2 — ส่งหัวหน้า** (เน้น "ต้องตามใคร")
```
รายงานยาสั่งแล้วยังไม่มาส่ง (ณ <วันที่>)

วิกฤต — คลังเหลือ 0
1. <ยา> — ค้าง <n> วัน (<บริษัท>)

ใกล้หมด เหลือ 1-5 + ค้างนาน
2. <ยา> — เหลือ <n> ค้าง <n> วัน

ข้อสังเกต: <บริษัท> ค้าง <n> รายการ อาจมีปัญหาเชิงระบบ
```

## Do Not

- **อย่าตอบจากผลรอบก่อน** — ไฟล์เปลี่ยนระหว่างวัน ต้องรันใหม่ทุกครั้ง
- **อย่าใช้ Supabase ตอบคำถามนี้** — DB เก่ากว่า Excel เสมอ
- **อย่านับของ `รอตรวจรับ` เป็นของพร้อมจ่าย** — ยังจ่ายไม่ได้ตามระเบียบ
- **อย่าเงียบเมื่อเจอข้อมูลขัดแย้ง** — แจ้ง user ให้คลังตรวจสอบเสมอ
- **อย่าแก้ไฟล์ Excel** — สกิลนี้อ่านอย่างเดียว
- **อย่ารายงานว่า checkbox ผิด** ถ้ายังไม่เช็ค `สถานะการซื้อ`
