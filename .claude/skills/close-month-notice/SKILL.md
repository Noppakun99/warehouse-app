# Skill: close-month-notice

user สั่ง 03/11/2569: **ทำทุกเดือนหลังปิดยอด** ทำต่อจาก `anthropic-skills:upgrade-month-v3` และรายงานส่งบัญชี

## ขั้นตอน

1. ต้องมีชีท `Master_<เดือนที่ปิด>` แล้ว · ไม่ต้องปิด Excel (สคริปต์อ่านอย่างเดียว)
2. รันสถานะ PO ล่าสุด: `python -B scripts/po_match.py` (ไม่ใส่ `--commit`)
3. สร้างข้อความ: `python -B scripts/close-month-notice.py --month ต.ค.69`
   - ใช้ไฟล์ `สุรปยอด ส่งบัญชี*.xlsx` ล่าสุดใน `OneDrive\Documents` · ระบุไฟล์เองด้วย `--register <path>`
   - เซฟที่ `Desktop\ยอดคงคลัง\ยอดคงคลังส่งบัญชี\แจ้งจัดซื้อ_<เดือน>.txt`
4. อ่านหัวข้อ "ข้อสังเกตสำหรับคลัง" ก่อนส่ง (ส่วนนี้ไม่ส่งจัดซื้อ)
   - `⛔` ยอดทะเบียนไม่ตรง Master หรือบิลจับคู่ไม่ได้ = หยุด แก้ก่อน ห้ามบอกว่ายอดตรง
   - บิลตรวจรับแล้วแต่ไม่มีใบ ตร. ที่ใช้งานอยู่ = ถาม user ก่อนจัดเข้ากลุ่ม "ตรวจรับแล้ว"
5. ทวนชุด 1 ทีละจุดกับไฟล์ทะเบียน แล้วส่งข้อความ 2 ชุดให้ user ในกล่อง code block ไม่ใช้ตาราง markdown (ไลน์ไม่แสดงตาราง) · ขึ้นต้นคำตอบด้วย `Written for: เจ้าหน้าที่จัดซื้อ ส่งทางไลน์`
6. ก่อนสรุปงาน ถาม user ว่าส่งแล้วหรือยัง + จด `_บันทึกเพิ่ม.csv`
7. **ทะเบียนคงคลังรายเดือน (รายงาน 5 แฟ้ม DMSIC — ADR-0031)**: `npm run import:ledger -- --sheet Master_<เดือน>` (dry-run) → ยอด เวชภัณฑ์ยา/มิใช่ยา ต้องตรงแถว "ยอดรวมสุทธิ" คอลัมน์คงเหลือ ของ `แบบรายงานผลการตรวจสอบพัสดุ_<เดือน>.xlsx` เป๊ะ → `--commit` (เขียนงวดสถานะปิดแล้ว · งวดที่ปิดแล้วต้องมี `--reason`) · ไม่ตรง = หยุด ห้าม commit · ⛔ ห้ามกดปิดงวดในแอป/`closeLedgerPeriod` กับงวดนี้

## กติกาข้อความ

- **อ้างตำแหน่งเป็น "รอบที่ R (วันที่) ลำดับที่ N" ตามคอลัมน์ A ของทะเบียน ไม่ใช้ "แถว D5" แล้ว** (user สั่ง 20/11/2569 แทนกฎ 03/11) — คนแก้ไฟล์ดูลำดับที่ในไฟล์ ไม่ได้ดูเลขแถว Excel
  - ลำดับนับ 1 ใหม่ทุกรอบส่ง · ส่วน "มิใช่ยา" นับใหม่อีกชุด (เขียน "มิใช่ยา ลำดับที่ N") · ช่องลำดับว่าง = บิลที่ 2+ ของลำดับบน · **วันที่รอบซ้ำกันได้** (ต.ค.69 มี 22/10/69 สองรอบ) จึงต้องมี "รอบที่ R" นับตามหัวตารางในชีท
- **ทุกจุดต้องบอก: ลำดับที่ · PO · บิล · ค่าในทะเบียน → ค่าที่ต้องแก้ · เพราะอะไร** (user สั่ง 20/11/2569)
  - เลข PO เทียบ 3 แหล่ง: `PO ในบิล` (Master AW) · `PO ในระบบจัดซื้อ` (`_POจัดซื้อ_จับคู่บิล.csv` จับด้วยเลขบิล) · `PO ในทะเบียน` (ไฟล์พี่โก้) → "ขอแก้ PO ในทะเบียนเป็น X (บิลและระบบจัดซื้อตรงกัน) เพราะ PO Y ในระบบจัดซื้อเป็นของ <บริษัทอื่น>" · บิลกับระบบไม่ตรงกันเอง = ขอให้จัดซื้อตรวจ ไม่ระบุค่าที่ถูก
  - ชื่อบริษัท: "ในทะเบียนพิมพ์ A ขอแก้เป็น B เพราะชื่อบริษัทในบิลเป็น B" + รายการ รอบ/ลำดับ/PO/บิล ที่ผิดชื่อนี้
  - เลขโครงการ: บอกเหตุผล (จำนวนหลักต่างจากส่วนใหญ่ / เลขเดือนหลักที่ 3–4 ผิดช่วง)
  - ตัวอย่าง:
    ```
    - รอบที่ 1 (11/11/69) ลำดับที่ 2 · บิล IST260177652 ที แมน ฟาร์มาซูติคอล
      PO ในบิล 79.05 · PO ในระบบจัดซื้อ 79.05 · PO ในทะเบียน 75.05
      ขอแก้ PO ในทะเบียนเป็น 79.05 (บิลและระบบจัดซื้อตรงกัน) เพราะPO 75.05 ในระบบจัดซื้อเป็นของ เวสโก ฟาร์มาซูติคอล
    ```
- **ทุกจุดผิดที่เจอ → append `_บันทึกผิดพลาด.csv` ประเภทงาน `ส่งบัญชี` ทันที** (user สั่ง 20/11/2569 — ไฟล์พี่โก้ผิดบ่อย ต้องทำรายงานต่อ · memory `procurement-register-errors`) · จัดซื้อแก้แล้วค่อยกรอกวันที่แก้
- ชื่อที่ถูกมาจาก Master คอลัมน์ Q · ชื่อย่อที่ตัดท้าย เช่น `เบอร์ลิน ฯ` ไม่นับว่าผิด
- ชุด 2 แยกครบ: ส่งบัญชีแล้ว · ตรวจรับแล้วยังไม่ส่ง · ยังไม่ตรวจรับ แบ่งเป็น PO ของมาไม่ครบ กับ ของครบรอชุดตรวจรับ

## ที่สคริปต์ตรวจ และข้อจำกัด

- **ชื่อบริษัท:** เทียบกับ Master ด้วยเลขบิล
- **เลข PO:** รูปแบบผิด หรือไม่ตรงเลข PO ของบิลในชีทรับยา
- **เลขโครงการ:** ความยาวต่างจากส่วนใหญ่ หรือเลขเดือนไม่อยู่ใน 6 เดือนย้อนหลัง — ตรวจรูปแบบเท่านั้น เลขที่พิมพ์ผิดแต่รูปแบบถูกจับไม่ได้
- **ใช้ได้กับ snapshot ตั้งแต่ `Master_ต.ค.69`:** snapshot เก่ากว่าผังคอลัมน์ต่าง (AW ไม่ใช่เลข PO)
- **สถานะ PO:** ดูจาก `_POจัดซื้อ_จับคู่บิล.csv` ณ วันที่รัน ถ้าเน็ตล่มให้รันใหม่ก่อน อย่าใช้ไฟล์เก่า
