### 1. snapshot — คัดลอก 3 ไฟล์มาอ่าน
- บอกผู้ใช้เสมอว่าแต่ละไฟล์ **เซฟล่าสุดกี่โมง** และไฟล์ไหน **เปิดอยู่ใน Excel** → ข้อมูลที่ยังไม่เซฟจะไม่ถูกนับ ถ้าผู้ใช้เพิ่งบันทึกเบิก/รับ ให้เซฟก่อน
- ไฟล์ถูกแก้ระหว่างวันบ่อย — **ทุกครั้งที่ผู้ใช้สั่งรอบใหม่ ต้องเริ่ม snapshot ใหม่** ห้ามใช้ผลรอบก่อน

### 2. check — ตรวจสูตรเรทก่อนเชื่อสถานะ ⛔ ถ้า exit 2 หยุดถามผู้ใช้
ตรวจ: เดือนของคอลัมน์ E–P อ่านจาก**แถว 2** (ชีทจัดใหม่ 04/10/2569: 12 เดือนล่าสุดที่ปิดแล้ว เลื่อนเองตาม `TODAY()`) · P ต้องเป็นเดือนก่อนหน้า (ไม่ใช่ = ไฟล์ยังไม่ได้คำนวณใหม่ตั้งแต่ขึ้นเดือน) · สูตร Max/Avg/รวม3เดือน อ้างคอลัมน์ชุดเดียวกันทุกแถว (ปัจจุบัน N+O+P) · ยอดเบิกรายเดือนทุกช่อง (~5,500) ตรงกับชีทเบิก · Max/Avg/รวม3เดือน ตรงหน้าต่าง
- **หน้าต่างเรท = 3 เดือนล่าสุดที่ปิดแล้ว ไม่รวมเดือนปัจจุบัน** (ตั้งแต่จัดชีทใหม่ 04/10/2569 — สูตร `MONTH(TODAY())-10/-11` + `CHOOSE` เดิมเลิกใช้แล้ว ไม่ต้องสลับตอนขึ้นปีงบอีก)

### 3. plan — คำนวณแผน (ยังไม่เขียนอะไร) ⛔ แสดงผลให้ผู้ใช้ยืนยันก่อน apply
| ส่วน | กติกา |
|------|-------|
| **ยกเลิกแจ้ง → ย้ายไป Sheet1 (☐ + เหตุผล)** | หัวหน้าสั่งไม่ซื้อ → `plan --cancel "รหัส=เหตุผล"` (ใช้ซ้ำได้) — ไม่ลบทิ้ง เก็บประวัติแบบเดียวกับแถวเดิมใน Sheet1 ที่เขียนว่า "ให้แผนไทยแจ้งสั่งเอง" · **ต้องตั้งคอลัมน์ AI (ตัดออกจากบัญชี ,สั่งเมื่อขอ) = 📋 สั่งเมื่อขอ ในชีทวิเคราะห์แล้วเซฟ** (เดิมเขียนว่า AE — ย้ายเป็น AI ตั้งแต่จัดชีทใหม่ 04/10/2569) (plan เตือนถ้ายังไม่ได้ทำ) ไม่งั้นรอบหน้าจะกลับมาเป็นรายการใหม่ |
| **มาส่งแล้ว → ย้ายไป Sheet1** | มีรับสถานะ `การซื้อ` ของรหัสนั้น วันที่ **≥ วันที่แจ้ง (B)** — จับคู่**รหัสอย่างเดียว** · ติ๊ก ☑ ให้ถ้ายังไม่ติ๊ก (บอกผู้ใช้ว่าตัวไหน) · ☑ แล้วแต่หาการรับไม่เจอ → **ไม่ย้าย แจ้งเตือน** |
| **C วันที่ยาส่งล่าสุด** | วันรับ `การซื้อ` ล่าสุดของรหัส (ไม่สนหน่วย — หน่วยบรรจุเปลี่ยนตามรอบซื้อ) ไม่มีเลย = `-` |
| **อัพเดต I–T แถวที่ยังรอของ** | จับคู่ **รหัส+หน่วย** กับชีทวิเคราะห์ (ค่าคงเหลือ/ROP ผูกหน่วย) หน่วยไม่ตรง = ไม่แตะ + เตือน · **A, B, S (หมายเหตุที่คนพิมพ์) ห้ามแตะ** |
| **รายการใหม่** | V ∈ `หมดสต็อค` / `สั่งเพิ่ม` / `สั่งเพิ่ม ใกล้หมดอายุ` และ**ไม่ซ้ำกับรหัสที่ยังรอของ** (ตัวที่ของมาแล้วแต่ยังต่ำกว่า ROP แจ้งซ้ำได้ — ผู้ใช้เลือกแบบนี้ 2569-10-01) · B = วันที่แจ้ง · เรียง หมดสต็อค → ใกล้หมดอายุ → สั่งเพิ่ม |
| **หมายเหตุอัตโนมัติ (S)** | `สั่งเพิ่ม ใกล้หมดอายุ Exp.dd/mm/yyyy` (Exp ล่าสุดของ lot ที่ยังมีของ) · `แจ้งซ้ำ: ของมาแล้ว d/m/yy แต่ยังต่ำกว่า ROP` (เคยแจ้ง + มีของเข้าหลังรอบนั้น) |
| **หัวรายงาน** | A1 `UPDATE: วันที่ …` · O4 `คงเหลือ …` · P4 ช่วงเดือนของ "รวมทุกเดือน" · Q4 หน้าต่าง 3 เดือน |

- **สถานะใช้ค่าคอลัมน์ "สถานะ" (Z) ของชีทเท่านั้น ห้ามคำนวณ ROP เอง** — สมุนไพร/สั่งเมื่อขอ/ตัดออก คุมด้วยคอลัมน์ AI ในชีทอยู่แล้ว · ยาสั่งเมื่อขอที่ต้องสั่งตามวันหมดอายุ (ของอยู่ที่ห้องยา คลังมองไม่เห็น) ใส่ `Desktopยอดคงคลัง_นัดเตือน.csv` — `check-complete.py` เตือนเมื่อถึงวัน (สมุนไพรที่แจ้งซื้อได้มี 7 ตัว ดู CONTEXT.md)
- อ่าน **คำเตือน** ทุกข้อให้ผู้ใช้ฟัง

เทียบ report_out กับแผนและไฟล์ต้นฉบับ: ชุดรหัส = เดิม − ที่ย้าย + ใหม่ · ไม่มีรหัสซ้ำ · ตารางครอบถึงแถวสุดท้าย · แถวเดิมคอลัมน์ A B D–H S ไม่ถูกแตะ · C/I–T ตรงแผน · แถวใหม่ทุกช่องตรงแผน · Sheet1 เพิ่มตรงจำนวน ติ๊กครบ ไม่ซ้ำ · หัวรายงานเปลี่ยนแล้ว
(ทดสอบแล้ว: แกล้งแก้ 2 ช่อง → จับได้ 2 จุดพอดี)

### 6. publish — คัดลอกกลับ OneDrive
ล้มถ้า: ไฟล์เปิดอยู่ (ให้ผู้ใช้ปิด) · ไฟล์ถูกแก้หลัง snapshot (**เริ่มใหม่จากขั้น 1 ห้ามเขียนทับงานผู้ใช้**) · สำรอง `OneDrive\backup\รายงานการซื้อยา_69_backup_<เวลา>.xlsx` อัตโนมัติ

### 6b. สำเนารายงานรายรอบ — ⛔ ทำทุกรอบหลัง publish (user สั่ง 14/10/2569 — รอบ 9–14/10 เคยลืม)
`Desktop\ยอดคงคลัง\รายงานขอซื้อยา\รายงานการซื้อยา_<ว.ด.ปี ค.ศ.>.xlsx` (เช่น `_14.10.2026`) = **ชีท `รายงานซื้อยา` ชีทเดียว** (ไม่เอา Sheet1 / บริษัท_วันที่ล่าสุด_ราคา) คือฉบับที่ส่งหัวหน้า

### 7. line — ข้อความไลน์ตามยา (ไม่เขียนไฟล์)
- ขอบเขตเริ่มต้น: **หมดสต็อค + คงเหลือ < Avg/วัน × 7** (ไม่พอจ่ายสัปดาห์นี้) — ถ้าผู้ใช้อยากได้มากกว่านี้ ถามก่อน
- **รูปแบบ (user แก้แล้วส่งจริง 14/10/2569 — แทนแบบ "เรียน…/ขอบคุณมากครับ" ของ 02/10)**: ขึ้นต้น "ฝากพี่ติดตามยา ตามรายการด้านล่างนี้ครับ" · ไม่มีคำปิด · เหตุผลลงท้าย "ครับ" ทุกข้อ · จำนวน `N x หน่วย` · **กลุ่ม【ด่วน】อยู่บนแยกหัวข้อ = นิยามเดียวกับอักษรสีแดงในรายงาน (หมด / คงอยู่ได้อีก ≤ Lead Time / หน่วยงานขอเบิกภายใน 14 วันแล้วไม่ได้ของ — เดิมใช้แค่ข้อสุดท้าย เปลี่ยน 22/10/2569)** แล้วตามด้วย【ติดตามทั่วไป】 (เลขข้อต่อเนื่อง) — ตัวอย่างเต็มใน memory `line-message-polite`
- ขอเบิกแล้ว**จ่ายได้บางส่วน**ก็นับ (รวมแถว lot ของคำขอเดียวกัน) — เดิมนับเฉพาะจ่าย 0 · ส่วนตรวจสอบลิสต์ "ขอเบิกไม่ครบแต่ไม่อยู่ในไลน์" (คลังมีของ เช่น รอตรวจรับ) ให้ user ตัดสินว่าจะเพิ่มไหม
- **เหตุผลต่อท้ายทุกตัว จากข้อมูลจริงเท่านั้น**: แจ้งไป N วันยังไม่มีของเข้า · ของรอบที่แจ้งมาส่งแล้วแต่ไม่พอ · เพิ่งแจ้งวันนี้ · ขอเบิกแล้วไม่มีจ่าย (แถวเบิกจำนวน 0 ที่มี "จำนวนที่ขอ") · เหลือไม่พอสัปดาห์นี้ — เหตุผลที่ข้อมูลไม่มี (เช่น "ห้องยาไม่มีของ", "ยา TB ขาดไม่ได้") ต้องมาจากผู้ใช้ ใส่ผ่าน `--note รหัส=ข้อความ`
- "เบิกล่าสุด" ไม่นับแถว `บันทึกเท่านั้น` / `แก้ไขระบบ` และแถวจำนวน 0
- ถ้าสคริปต์บอก "ไม่มีแถวแจ้งสั่งในรายงานปัจจุบัน" → ทำขั้น 1–6 ให้รายงานครบก่อนส่งไลน์
- บอกแหล่งข้อมูล (ไฟล์ + ชีท + เวลาเซฟ) ไว้**นอก**ข้อความที่จะ copy
