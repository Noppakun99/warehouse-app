# Skill: report-to-head

รายงานมีโครงเดียว เลือกได้ 2 แบบ คือ **แบบทั่วไป** กับ **แบบราชการ** · เนื้อหาต้องมาจากข้อมูลจริงเท่านั้น

เรียกแบบระบุเลยได้: `/report-to-head ทั่วไป <เรื่อง>` หรือ `/report-to-head ราชการ <เรื่อง>`

**ไม่ใช้กับงานที่มีรูปแบบของตัวเอง:** ตามยา/แจ้งซื้อรอบสัปดาห์ = `/purchase-request-report` · แจ้งจัดซื้อหลังปิดยอด = `/close-month-notice` · ยาค้างจ่าย = `drug-shortfall-report` · ใบของแถม = `/free-goods-report`

## ขั้นตอน

1. **เลือกแบบ + ผู้รับ** ไม่ต้องถามเมื่อคำสั่งบอกแบบชัดแล้ว: `ราชการ` `บันทึกข้อความ` `หนังสือราชการ` `เสนอผู้อำนวยการ` = แบบราชการ · `ทั่วไป` `ไลน์` `Excel` `ประเด็นประชุม` = แบบทั่วไป · **ไม่ชัดให้ถามด้วย AskUserQuestion ว่า "แบบราชการ หรือแบบทั่วไป" ห้ามเดา** · แบบทั่วไปต้องรู้ช่องทางด้วย · รายงานการซื้อยาและสำเนาแต่ละรอบส่งหัวหน้ากลุ่มงาน ไม่ใช่หัวหน้าคลัง
2. **ตรวจตัวเลขกับแหล่งจริงในรอบนี้** อย่าลอกจาก memory หรือ handoff · ไฟล์ Excel ใน OneDrive อ่านจากสำเนา · สคริปต์ที่เขียนไฟล์ทุกครั้งที่รัน เช่น `close-month-notice.py` ห้ามรันเพื่อดูข้อมูล
3. **เติมโครงรายงาน** ด้านล่าง ช่องไหนไม่มีข้อมูลให้เขียนว่าไม่มี หรือถาม user ห้ามเดา
4. **จัดรูปแบบตามแบบที่เลือก** แล้วขึ้นต้นคำตอบด้วย `Written for: <ผู้รับ> <ช่องทาง>` (บรรทัดนี้ไม่อยู่ในตัวข้อความ)
5. **ส่งร่างให้ user ส่งเอง** Claude ไม่ส่งแทน · ก่อนสรุปงานถามว่าส่งแล้วหรือยัง แล้วจดตามหัวข้อ "หลังส่ง"

## โครงรายงาน

| ช่อง | เขียนอะไร |
|---|---|
| **สถานะ** | 1 บรรทัด อ่านแล้วหยุดได้และยังได้คำตอบที่ถูก |
| **ผลกระทบ** | จำนวน x หน่วย · มูลค่า · หน่วยงาน |
| **สาเหตุ** | เหตุและผล 1–2 ประโยค ไม่ลงชื่อสูตร ชื่อไฟล์ หรือเลขแถว เว้นแต่ผู้รับต้องใช้หาจุดแก้ |
| **ทำไมหลุด** | เฉพาะเรื่องที่ผิดพลาด ดูกติกาด้านล่าง |
| **ใครทำต่อ + ขั้นถัดไป** | ชื่อฝ่ายหรือคนที่รู้แน่ · ยังไม่รู้ให้เขียนว่ารอระบุ |
| **ช่วงข้อมูล + ข้อจำกัด** | ทุกตัวเลขต้องบอกช่วง และบอกสิ่งที่ยังไม่รวม เช่น "ยังไม่รวมคลังย่อย" |
| **ขอให้ตัดสินใจ** | ถ้ามี ให้ตัวเลือกพร้อมข้อมูล ไม่ตัดสินแทนหัวหน้า |

ใส่เฉพาะช่องที่มีประโยชน์กับเรื่องนั้น ไม่ต้องครบทุกช่อง

## ช่อง "ทำไมหลุด"

- ใช้เมื่อแก้แล้วหรือรู้ต้นเหตุแล้ว ถ้ายังไม่รู้ให้เขียนว่า "ยังไม่ทราบสาเหตุ" ไม่เขียนข้อสันนิษฐานเป็นข้อสรุป
- เล่าช่องโหว่ของขั้นตอน ไม่โทษคน: "ติ๊กตรวจแค่ใบ → บิล ไม่ได้นับตัวบิล" ไม่ใช่ "เจ้าหน้าที่ลืมนับ"
- บอกว่าตรวจอะไรแล้ว อะไรยังไม่ได้ตรวจ และบอกวิธีกันซ้ำเฉพาะที่ทำจริงหรือเสนอจริง

## แบบทั่วไป

ข้อความไลน์ส่งเป็น code block ไม่ใช้ตาราง markdown เพราะไลน์ไม่แสดงตาราง · จำนวนเขียน `<จำนวน> x <หน่วย>` ทุกที่

**ไลน์หัวหน้า** บรรทัดแรกบอกเรื่องและผล ตามด้วย bullet ขึ้นต้น `-` · สุภาพพอดี ไม่ต้อง "เรียนพี่/รบกวนพี่" ยาว · มีเหตุผลจากข้อมูลจริงทุกรายการที่ขอให้ทำ

**ไลน์กลุ่มห้องยา** `แจ้งจากคลังยา :` แล้ว bullet ละเรื่อง ใจความ + ขอบเขต จบเลย ไม่ขยายผลกระทบ ไม่ใส่เหตุผลยาว

**ไลน์แจ้งซื้อด่วน (ยาหมด/ค้างจ่าย)**
```
แจ้งซื้อด่วนครับ — <ชื่อยา> (<ชื่อในระบบ>) หน่วย: <หน่วย> (<ขนาดบรรจุ>)

-คงเหลือในคลัง: <N> <หน่วย> ค้างจ่าย: <หน่วยงาน> <N> <หน่วย>
-ยอดเบิก: เดือน <ด.> รวม <N> <หน่วย> แจกรายวัน + หน่วยงาน
-ก่อนหน้า เคยซื้อ <บริษัท> ราคา <ราคา> บาท/<หน่วย> ซื้อครั้งล่าสุด <ว/ด/ปป>
ขอบคุณครับ
```
ไม่เขียนหัวข้อ "ทำไมยังไม่ได้แจ้งซื้อ" และไม่โยนว่าหัวหน้าเคยสั่งไม่เอา · ส่งแล้วเพิ่มเข้ารายงานแจ้งซื้อด้วย `/purchase-request-report`

**Excel ให้หัวหน้า** สรุปอยู่บน ตารางอยู่ล่าง เก็บใน `Desktop\ยอดคงคลัง\พี่โบว์` · ยอดรวมและอัตราเป็นสูตร ไม่พิมพ์ผลลัพธ์ · เก็บจำนวนเป็นตัวเลข แล้วใช้ number format `#,##0" x 1000 เม็ด"` · คำนวณและตรวจหน้าตาด้วย Excel COM (`recalc.py` ของสกิล xlsx ใช้บนเครื่องนี้ไม่ได้) · ไฟล์ที่ส่งแล้วให้เพิ่มลงไฟล์เดิมหรือตั้งชื่อใหม่ ไม่สร้างทับ

**ประเด็นพูดในประชุม** bullet สั้นตามลำดับที่จะพูด ใส่ตัวเลขที่ต้องอ้างในบรรทัดนั้น

## แบบราชการ

อ่าน [references/official-letter.md](references/official-letter.md) ก่อนทุกครั้ง · ค่าเริ่มต้นคือบันทึกข้อความถึงผู้อำนวยการ ผู้รับนอกโรงพยาบาลให้ถาม user ก่อน

| ช่องในโครงรายงาน | ไปอยู่ตรงไหนของหนังสือ |
|---|---|
| สถานะ · ช่วงข้อมูล | `เรื่อง` และภาคเหตุ |
| สาเหตุ · ทำไมหลุด | ภาคเหตุ เขียนเป็นข้อเท็จจริงของขั้นตอน |
| ผลกระทบ · ใครทำต่อ + ขั้นถัดไป | ภาคความประสงค์ · หลายเรื่องให้แยกข้อ |
| ขอให้ตัดสินใจ | ภาคสรุป เช่น `จึงเรียนมาเพื่อโปรดพิจารณา` |
| ข้อจำกัด | ต้องอยู่ในเนื้อหนังสือ ห้ามตัดออก |

- ภาษาทางการ ไม่ใช้ `ครับ` คำพูด คำย่อที่ผู้อ่านนอกคลังไม่รู้จัก หรือ bullet แบบแชต
- ตารางยาวแยกเป็นเอกสารแนบ แล้วเขียน `(ตามเอกสารแนบ)` ในเนื้อหนังสือ · ใช้รูปแบบ Excel ของแบบทั่วไปเป็นเอกสารแนบได้
- ผลลัพธ์เริ่มต้นคือร่างข้อความให้ user ตรวจ · สร้างไฟล์ Word เมื่อ user สั่ง และถามชื่อ ตำแหน่ง โทรศัพท์ รหัสหนังสือก่อน

## กฎที่ห้ามพลาด

- **ห้ามแต่งข้อเท็จจริง** ตัวเลข สาเหตุ ผู้รับผิดชอบ วันที่ · ไม่แน่ใจให้เขียนว่ายังไม่ยืนยัน อย่าตัดข้อจำกัดออกเพื่อให้ข้อความดูเรียบร้อย
- **ไม่ตัดเลขอ้างอิงออก** เลข PO · เลขบิล · บย. · สบ. · ตร. · LN · VX เพราะหัวหน้าใช้ตามเรื่องต่อ
- **ไม่บอกหัวหน้าว่าควรทำอะไร** ให้ข้อมูลและตัวเลือก · ถ้า user ขอให้เขียนคำแนะนำจึงเขียน โดยแยกจากข้อเท็จจริงให้ชัด
- **แก้เกิน 2 รอบ** ให้ถามว่าเข้าใจผู้รับหรือเรื่องผิดตรงไหน อย่าปรับไปเรื่อย ๆ
