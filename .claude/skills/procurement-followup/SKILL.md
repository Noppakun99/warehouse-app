# Skill: procurement-followup — ทวงงานในกลุ่มไลน์ "จัดซื้อยา"

user สั่ง 23/11/2569 · คลังมีหน้าที่**ทวง** (ตรวจรับ · PO · บิล) ใช้ข้อเท็จจริง ไม่กล่าวโทษ (memory `head-pending-inspection-report`)

## กฎข้อความ (user กำหนด 23/11/2569)

- **ส่งในกลุ่มไลน์ "จัดซื้อยา" ทั้งหมด** · **1 ข้อความ = 1 คน ขึ้นต้นด้วยชื่อคนนั้นก่อน** ไม่เรียกรวม 3 คน
- **ผู้รับตามขั้นที่ค้างในระบบจัดซื้อ** (`สถานะในระบบ` ใน `_POจัดซื้อ_จับคู่บิล.csv`):

  | ขั้นในระบบ | ถึง | ขึ้นต้น |
  |---|---|---|
  | `รอตรวจรับ` | **ชมพู่** (ผู้ตรวจรับ — ในไลน์ชื่อ `Chom`) | `ชมพู่ ครับ แจ้งมีรายการตรวจรับตามรายการยาดังนี้ครับ` |
  | `รอส่งทำชุดตรวจรับ` · ผล `ยอดบิลเกิน/ขาดยอด PO` | **พี่โก้** (จัดซื้อ `~Ko~`) | `พี่โก้ ครับ แจ้งมีรายการรอทำชุดตรวจรับ/แก้ข้อมูล PO ตามรายการยาดังนี้ครับ` |
  | `รอยามาส่ง` (ไม่มีของ · ส่งมาบางส่วน) | **พี่โบว์** (หัวหน้า) | `พี่โบว์ ครับ แจ้งมีรายการยายังไม่มาส่ง ตามรายการยาดังนี้ครับ` |

- **แบ่ง 2 หัวข้อ `【ด่วน】` ก่อน แล้ว `【ตามปกติ】`** เลขข้อต่อเนื่อง
  - **ด่วน** = ไม่มีจ่าย (คลังจ่ายได้ 0) · จ่ายไม่พอ (หน่วยงานขอใน 14 วันแล้วได้ไม่ครบ และยังไม่มีจ่ายตามทีหลัง) · คงเหลือพอใช้ ≤ 7 วัน — บรรทัดย่อยบอกเหตุผลรายยา
  - **ตามปกติ** = เกินกำหนด: รอตรวจรับ/ทำชุดเอกสารเกิน 5 วันทำการ (หัวหน้า 20/11: ชุดตรวจรับไม่ควรเกิน 5 วันทำการ) · PO ออกเกิน 10 วันยังไม่มาส่ง · ยอด PO ไม่ตรงบิล — **บิลที่ยังอยู่ในกำหนดไม่ใส่** (สคริปต์บอกจำนวนนอกข้อความ · `--all` ดูทั้งหมด)
- ทุกข้อ: ยา + จำนวน `N x หน่วย` · บิล · PO · บริษัท · วันของมา · ขั้นในระบบ · วันทำการ · ทวงแล้วเมื่อไร (เฉพาะที่ทวงในกลุ่มนี้) · ปิดด้วยคำขอ 1 บรรทัด
- **ห้ามเสนอปรับวันขนยาให้ผู้ตรวจรับ** · ห้ามเดาเหตุผลที่ข้อมูลไม่มี

## ขั้นตอน

0. **⛔ ก่อนทำร่างทุกครั้ง: ดึงรายการตามยาเดิม + ข้อสังเกตหัวหน้า** (user สั่ง 25/11/2569 — ร่าง 25/11 ขึ้น Valproate PO 163.05 โดยไม่มีโน้ต "หัวหน้าแจ้ง 24/11: มาวันพฤหัส" ทั้งที่อยู่ในทะเบียนแล้ว)
   - อ่าน `_ทะเบียนตามยา.csv` ทุกแถวที่ยังไม่ปิด โดยเฉพาะคอลัมน์ `หัวหน้าตอบ` · `วันที่ตอบ` · `ต้องทำต่อ` — สคริปต์ข้อ 2 พิมพ์หัวข้อ "ข้อสังเกตหัวหน้าในทะเบียนตามยา" ให้แล้ว
   - **คำตอบหัวหน้าต้องอยู่ในโน้ตของข้อนั้นในร่างทุกครั้ง** — สคริปต์ใส่บรรทัด `(หัวหน้าแจ้ง <วันที่>: …)` เองเมื่อจับรหัส/PO ได้ · ข้อที่จับไม่ได้ (รหัส `-` และไม่มีเลข PO) **ใส่เองแล้วบอก user**
   - หัวหน้าตอบทางไลน์/ต่อหน้าแต่ยังไม่อยู่ในทะเบียน → **ลงทะเบียนก่อน** แล้วค่อยรันสคริปต์
   - ทวงคนไหนไปแล้วเมื่อวาน/วันนี้ (`ทวงแล้ว` ล่าสุด) → ถาม user ก่อนใส่ข้อความถึงคนนั้นซ้ำ (25/11: พี่โบว์ทวงไปแล้ว 24/11 user ให้งดทวงวันนี้)
1. **ระบบจัดซื้อให้เป็นปัจจุบัน**: `python -B scripts/po_match.py` (dry-run — เขียนแค่ CSV)
2. **สร้างร่าง**: `python -B .claude/skills/procurement-followup/scripts/followup.py [--only ชมพู่|พี่โก้|พี่โบว์] [--all]` — อ่านอย่างเดียว ใช้ข้อมูล 2 ฝั่ง:
   - ระบบจัดซื้อ: ขั้น + ผลจับคู่บิล (CSV) · PO ↔ รหัสยาใช้ `po_match` ของ `/purchase-request-report` (pr.py) ตัวเดียวกัน
   - คลัง: Master `สถานะตรวจรับ` + `คงเหลือหลังจ่าย` (จ่ายได้ = ไม่นับรอตรวจรับ/lot หมดอายุ) · ชีทเบิก W/X 14 วัน (หน่วยงานค้างจ่าย) · วิเคราะห์สั่งซื้อ Avg/วัน · `_ทะเบียนตามยา.csv` (ทวงล่าสุด = ช่องทางขึ้นต้น `ไลน์กลุ่มจัดซื้อยา` รวม `(ฝากหัวหน้าตามยา)` · ข้อสังเกตหัวหน้า = คอลัมน์ `หัวหน้าตอบ` ยกเว้น `ไม่ได้ตอบ`)
3. **ตรวจส่วน "ไม่ต้องทวง"** ก่อนส่ง — บอก user ไม่ใส่ในข้อความ:
   - ระบบขึ้น `ตรวจรับเรียบร้อย`/`ส่งบัญชีแล้ว` แต่ Master ยังรอตรวจรับ = **คลังต้องลงตรวจรับเอง** (หารูปตรวจรับ)
   - Master รอตรวจรับแต่ไม่พบบิลในระบบ (บริจาค · ก่อนเริ่มใช้ระบบ) = ถาม user
   - **เลข PO บนบิล ≠ ระบบ** → ข้อความแยกถึงพี่โก้ เทียบเลข 3 ทาง ระบบ/ใบ PO/บิล — ขั้นตอน + รูปแบบอยู่ `/bill-entry` ข้อ 8 (user สั่ง 23/11/2569)
   - **ยาบริจาค (บิล `…-บริจาค` ไม่มี PO) ต้องตรวจรับ แต่ผู้ตรวจรับคือ พี่หนุ่ม ซึ่งไม่อยู่ในกลุ่มจัดซื้อ** (user ยืนยัน 23/11/2569) → แยกเป็นข้อความต่างหาก "ถึง พี่หนุ่ม (ไลน์ส่วนตัว)" ขึ้นต้น "แจ้งมีรายการยาบริจาครอตรวจรับดังนี้" (ยา · จำนวน x หน่วย · lot/Exp · บิล · บริษัท · วันมา) ห้ามรวมในข้อความชมพู่
4. **ทบทวนร่างกับเรื่องที่ตัดสินแล้ว** (memory) ก่อนส่ง เช่น PO 030.05 รอ Lasix GPO (หัวหน้า 20/11) · Remdesivir หัวหน้าซื้อเอง (สคริปต์ตัดออกจากข้อความพี่โบว์แล้ว · ในข้อความชมพู่ยังขึ้นได้) · ยา TB ไม่ด่วน — ปรับข้อความได้ แต่ตัวเลข/วันที่ต้องมาจากสคริปต์
5. ให้ user ดู → user ส่ง → **ลง `_ทะเบียนตามยา.csv` ทุกข้อ** (ช่องทาง `ไลน์กลุ่มจัดซื้อยา` — สคริปต์ใช้คำนี้นับ "ทวงแล้ว") + เก็บข้อความ `Desktop\ยอดคงคลัง\บันทึกการทำงาน\ไลน์กลุ่มจัดซื้อ_<เรื่อง>_<ว.ด.ปป>.txt` + `_บันทึกเพิ่ม.csv`

## สัมพันธ์กับ skill อื่น

- **ไลน์ตามยารายสัปดาห์ถึงหัวหน้า** (รายงานแจ้งซื้อ + หัวข้อด่วน/ของมาแล้ว/ติดตามทั่วไป) ยังเป็น `/purchase-request-report` ขั้น 7 — skill นี้คือการทวงรายขั้นในกลุ่มจัดซื้อ ใช้ `po_match`/`load_po` ของ pr.py ร่วมกัน (แก้ `PO_ALIAS` ที่ pr.py ที่เดียว)
- หมายเหตุใบเบิกจ่ายไม่ครบต้องบอกสถานะเดียวกับข้อความนี้ (รอตรวจรับ/แจ้งซื้อแล้ว/PO) → `/dispense-entry`

## ข้อจำกัดที่รู้

- วันทำการนับ จ.–ศ. ยังไม่หักวันหยุดราชการ — ช่วงวันหยุดยาวให้แก้ตัวเลขเองก่อนส่ง
- ระบบจัดซื้อมีแค่ชื่อย่อที่จัดซื้อพิมพ์ — PO ↔ รหัสจับด้วยชื่อ 6 ตัวอักษร + ขนาด (ไม่ตรง = ไม่ขึ้นเหตุผลด่วนในข้อความพี่โบว์ · เพิ่ม `PO_ALIAS` ใน pr.py)
- "ค้างจ่าย" นับจากแถวเบิกที่มี W/X ใน 14 วัน · จ่ายตามทีหลังแล้ว (มีแถวจ่าย > 0 ของรหัส+หน่วยงานเดียวกันหลังวันขอ) = ไม่นับ
