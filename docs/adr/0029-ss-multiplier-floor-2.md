# 0029. ตัวคูณ Safety Stock ขั้นต่ำ ×2 ทุกกลุ่ม VEN (ตามชีทวิเคราะห์สั่งซื้อ)

- **Status:** Accepted — 20/10/2569 (user เลือก "แก้แอปเป็น ×2 ตาม Excel" · ยังไม่ได้คำตอบหัวหน้าว่าเป็นค่าถาวรหรือชั่วคราว)
- **Date:** 2026-10-20
- **เกี่ยวข้อง:** [ADR-0001](0001-reorder-recompute-vs-import.md) (Excel = source of truth ของสูตร) · [ADR-0002](0002-blank-ven-defaults-essential.md) (VEN ว่าง = ×1.5 — ตอนนี้ไม่มีผลเพราะขั้นต่ำ ×2 ยกทับ)

## Context

ชีทวิเคราะห์สั่งซื้อใน `ยอดคลังยา_69.xlsm` คอลัมน์ AH (ตัวคูณ SS) = `MAX(2, IFS(VEN="V",2, VEN="E",1.5, VEN="N",1))` → **ได้ ×2 ทุกแถว**:
- ตรวจ 24/08/2569 ([docs/handoff-dispense-rate-2026-08-24.md](../handoff-dispense-rate-2026-08-24.md) §B4): 451/451 แถว (V 61 · E 282 · N 108)
- ตรวจ 20/10/2569: 457 แถว (V 61 · E 282 · N 114)

แอปใช้ V×2 / E×1.5 / N×1 ตาม CONTEXT.md เดิม ผลคือ SS ของแอปต่ำกว่าชีท 25% (E) และ 50% (N) รวมประมาณ 390 รหัส ทำให้ ROP ต่ำกว่า และสถานะ/จำนวนแนะนำสั่งไม่ตรงกับที่หัวหน้าใช้สั่งซื้อจริงจากชีท (Rule #13: SS ต้องมีนิยามเดียวทั้งระบบ · Dashboard อ่าน `inventory.safety_stock` จากชีทซึ่งเป็น ×2 อยู่แล้ว)

## Decision

แอปใช้สูตรเดียวกับชีท: **ตัวคูณ = `MAX(SS_MIN_MULTIPLIER, ตัวคูณ VEN)`** โดย `SS_MIN_MULTIPLIER = 2` ([src/lib/reorder.js](../../src/lib/reorder.js) `analyzeDrug`)
- เก็บ `RISK_MULTIPLIER` (V2/E1.5/N1) และ default 1.5 ของ VEN ว่างไว้ตามเดิม ไม่ลบ เพื่อให้ยกเลิกขั้นต่ำได้ด้วยการแก้ค่าคงที่ตัวเดียว
- `computeSafetyStock(avgDay, mult)` ยังรับตัวคูณตรงๆ เหมือนเดิม ขั้นต่ำอยู่ใน `analyzeDrug` จุดเดียว
- `analyzeDrug` คืน `ssMult` (ตัวคูณที่ใช้จริง) ให้ UI แสดง · ป้ายใน dropdown VEN บอกว่า E/N "ใช้ ×2 ตามชีท" (Rule #6: ตัวเลขที่แสดงต้องตรงค่าที่คำนวณ)

## Consequences

- SS/ROP/จำนวนแนะนำสั่งในแอปตรงชีท เช่น Para 500 (1000227, VEN E): SS 55 · ROP 76 · แนะนำสั่ง 11 (golden test 10)
- ป้าย VEN ยังมีประโยชน์ในการจัดกลุ่ม แต่ตอนนี้ไม่มีผลกับการคำนวณ
- ยา E/N มีของในคลังมากขึ้น (SS สูงขึ้น) แลกกับความเสี่ยงยาขาดที่ลดลง
- **ถ้าหัวหน้ายืนยันว่า `MAX(2, …)` เป็นของชั่วคราว** → ตั้ง `SS_MIN_MULTIPLIER = 0` (หรือลบ `Math.max`) แก้ golden test 1/4/10/11 + ชุดทดสอบใน ReorderApp + ป้าย dropdown แล้วเปลี่ยน ADR นี้เป็น Superseded · และเตือนให้แก้สูตร AH ในชีทด้วย ไม่งั้น Dashboard (อ่าน SS จากชีท) กับหน้าวิเคราะห์จะไม่ตรงกันอีก

## Alternatives considered

- **คงแอปไว้ที่ V2/E1.5/N1 จนกว่าหัวหน้าจะตอบ** — ถูกต้องตามนิยาม VEN เดิม แต่ตัวเลขในแอปต่างจากชีทที่ใช้สั่งซื้อจริงไปเรื่อยๆ (ต่างมาตั้งแต่อย่างน้อย ส.ค.69) · user เลือกตามชีท
- **ลอกค่า AH จากชีทเข้า DB รายรหัส** — ตรงชีทแน่นอน แต่ขัด ADR-0001 (แอปคำนวณเอง import แค่ VEN/exclude) และค่าจะค้างเมื่อชีทเปลี่ยน
