# 0030. รายการแจ้งซื้อในแอป = นำเข้าจากรายงานแจ้งการสั่งซื้อยาแบบแทนทั้งชุด + สถานะสดจากบิลซื้อ

- **Status:** Accepted — 14/11/2569 (user เคาะแบบ (ก) "บาง")
- **Date:** 2026-11-14
- **เกี่ยวข้อง:** [ADR-0001](0001-reorder-recompute-vs-import.md) (ตัวเลขวิเคราะห์คำนวณสดในแอป) · [ADR-0027](0027-excel-is-source-of-truth-for-inventory-and-dispense.md) (Excel เป็นตัวจริง) · CONTEXT §รายงานแจ้งการสั่งซื้อยา · §แจ้งแล้วเงียบ

## Context

คลังแจ้งซื้อยาผ่านไฟล์ `รายงานการซื้อยา_69.xlsx` (สกิล `/purchase-request-report`) — ชีท `รายงานซื้อยา` = รายการที่รอของ · `Sheet1` = ประวัติที่ย้ายออก (☑ มาส่งแล้ว · ☐ ยกเลิก) · ในแอปไม่มีใครเห็นว่ายาตัวไหน "แจ้งซื้อไปแล้ว" ผู้เบิกจึงถามซ้ำ และหน้าวิเคราะห์สั่งซื้อไม่บอกว่ายาที่ต่ำกว่าจุดสั่งถูกแจ้งไปแล้วหรือยัง

รายงานมี 24 คอลัมน์ แต่ส่วนใหญ่ (คงเหลือ · SS · ROP · จำนวนแนะนำ · มูลค่า) เป็น snapshot ของวันที่ทำรายงาน ซึ่งแอปคำนวณสดได้อยู่แล้ว (ReorderApp · บัตรยา)

## Decision

1. ตาราง `purchase_request` เก็บเฉพาะข้อมูลที่เกิดในรายงานเท่านั้น: รหัส · ชื่อ · หน่วย · **วันที่แจ้ง** · **สถานะตามช่องติ๊ก** (`รอ`/`มาส่งแล้ว`/`ยกเลิก`) · เหตุผล · หมายเหตุ · ชีท+เลขแถวต้นทาง — **ไม่ลอกคอลัมน์ตัวเลข** (snapshot จะขัดกับ ReorderApp/บัตรยา — Rule #6/#13)
2. นำเข้าแบบ **แทนทั้งชุด** ทุกครั้ง (CLI `npm run import:purchase` · dry-run ก่อน · สำรองก่อนเขียน) — Excel เป็นตัวจริง แอปไม่มีปุ่มแก้
3. **"มาส่งแล้ว" คำนวณสด** = มีบิล `การซื้อ` ของรหัสนั้นวันรับ ≥ วันที่แจ้ง (ตรงนิยาม CONTEXT) · Excel ติ๊กแล้วแต่ไม่เจอบิล → ยังถือว่ามาส่งแล้ว · ยกเลิกชนะบิล · ตรรกะอยู่ `requestState` ใน `src/lib/purchaseReportSheet.js` ที่เดียว
4. แสดง 3 ที่: บัตรยา (ทุก role — ผู้เบิกเห็นวันที่+เหตุผล · หมายเหตุเฉพาะ staff/admin) · ป้ายในตารางวิเคราะห์สั่งซื้อ · แท็บ "แจ้งซื้อแล้ว" ใน ReorderApp

## Consequences

- ป้ายในแอปสดเท่าวันที่นำเข้าล่าสุด — แจ้งซื้อรอบใหม่ใน Excel แล้วต้องนำเข้าอีกรอบ (เพิ่มเป็นขั้นในสกิล `/purchase-request-report` หลัง publish)
- ของมาแล้วแต่ Excel ยังไม่ติ๊ก แอปรู้เองจากบิล (14/11/2569 พบ 29 แถว) · แท็บแสดงจำนวนนี้ให้ไปย้ายในไฟล์
- ยาที่แจ้งซ้ำหลายรอบมีหลายแถว (ไม่มี unique key) — ป้ายใช้ใบที่ยังรอของเก่าสุด + จำนวนใบ
- ถ้าวันหน้าอยากแจ้งซื้อในแอปแทน Excel ต้องเปลี่ยน ADR นี้ (ตอนนี้ import ลบของเดิมทั้งหมดทุกรอบ)

## Alternatives considered

- **(ข) ลอกทั้ง 24 คอลัมน์** — ตัวเลข snapshot ขัดกับที่แอปคำนวณสด ผู้ใช้ต้องเดาว่าเชื่อตัวไหน
- **ทำหน้าแจ้งซื้อในแอปแทนไฟล์** — ต้องย้ายเกณฑ์/เพดานพื้นที่/ข้อความไลน์ทั้งหมดใน `pr.py` มาด้วย ใหญ่เกินรอบนี้
- **diff insert/update แทนแทนทั้งชุด** — ไม่มี key ที่คงที่ (แถวถูกย้ายระหว่างชีท เลขแถวเปลี่ยน) ได้ความซับซ้อนโดยไม่ได้ประโยชน์ เพราะแอปไม่เก็บข้อมูลของตัวเองในตารางนี้
