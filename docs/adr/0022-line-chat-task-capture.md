# ADR-0022: เก็บข้อความกลุ่ม LINE เพื่อกันงานที่สั่งผ่านแชทตกหล่น

วันที่: 2026-09-04 · สถานะ: **Accepted** · เกี่ยวข้อง: [ADR-0016](0016-anon-key-full-db-access.md)

## บริบท

หัวหน้าและเจ้าหน้าที่คลังสั่งงานกันในกลุ่ม LINE เป็นหลัก งานจำนวนหนึ่งตกหล่นเพราะไม่ได้อ่าน
หรืออ่านแล้วลืมทำ ไม่มีที่ไหนบันทึกว่า "เรื่องนี้สั่งไว้แล้วยังไม่ได้ทำ"

สภาพจริงที่ตรวจแล้ว:

- LINE Messaging API **ไม่มี endpoint อ่านประวัติข้อความย้อนหลัง** — สิทธิ์ผู้สร้างกลุ่มไม่ช่วย
  บอทได้เฉพาะข้อความที่เข้ามาทาง webhook นับจากวันที่เปิดเท่านั้น
- ประวัติเก่าดึงได้ทางเดียวคือ export จากมือถือเป็นไฟล์ `.txt` แล้วนำเข้า
- ไฟล์ export มี **2 รูปแบบที่ต่างกันคนละเรื่อง** (แชทกลุ่มใช้ TAB + พ.ศ. + `[รูป]`;
  แชทเดี่ยวใช้ช่องว่าง + ค.ศ. + `รูป`) — วัดจากไฟล์จริง 4,758 ข้อความ
- กลุ่มที่ใช้คุยงานคือกลุ่มชื่อ "รหัสล็อคคลังยา" ซึ่ง **ใช้แจ้งรหัสประตูคลังยา/คลังน้ำเกลือปนอยู่ด้วย**
- ระบบไม่มีทางรู้เองว่าข้อความไหนคือคำสั่งงาน — `"ฝากตรวจสอบยา"` กับ `"เค"` หน้าตาเหมือนกันในสายตาโปรแกรม

## การตัดสินใจ

**1. เก็บทุกข้อความดิบ แต่ปิดตารางจาก client สนิท**

ตาราง `line_message` เปิด RLS **โดยไม่ใส่ policy** ตาม [ADR-0016 กฎข้อ 1](0016-anon-key-full-db-access.md)
การอ่าน/เขียนผ่าน edge function ที่ถือ `service_role` เท่านั้น (`line-webhook` เขียน, `line-tasks` อ่าน)

เหตุผล: anon key อยู่ใน bundle ที่ browser โหลด ใครเปิด DevTools ก็หยิบได้ ถ้าเก็บแชทงานไว้ในตาราง
ที่ client อ่านได้ ก็เท่ากับเปิดบทสนทนาภายในให้คนนอกอ่าน

**2. รหัสเข้าสถานที่ไม่ลง DB เลย — กรองทิ้งทั้งแถวตั้งแต่ต้นทาง**

`containsDoorCode()` ตัดข้อความที่มีรหัสประตูออกทั้งแถว ทั้งฝั่ง import และฝั่ง webhook
**ไม่ใช่กลบตัวเลข** เพราะข้อความรอบๆ มักบอกว่าเปลี่ยนรหัสเพราะอะไร ซึ่งอ่อนไหวเองอยู่แล้ว

⚠️ กับดัก: คำว่า "รหัส" ในกลุ่มนี้หมายถึง **รหัสยา** ด้วย (`LRI 1000ml รหัส 12`) ตัวกรองจึงต้อง
แยกด้วยบริบท ไม่ใช่เจอคำว่ารหัสแล้วตัดทั้งหมด — วัดแล้วตัดถูก 16 แถวจาก 4,758 (0.3%)

**3. ดักคำแล้วให้คนยืนยัน ไม่ตัดสินแทน**

ข้อความที่เข้าเกณฑ์ได้สถานะ `candidate` (รอยืนยัน) คนกดยืนยันเป็น `task` → `done`
lifecycle: `candidate → task → done` (หรือ `dismissed` ถ้าไม่ใช่งาน)

คำที่ดัก: `@All อย่าลืม ด่วน ช่วย ฝาก เช็ค ตรวจสอบ รบกวน แก้ไข` + ต้องยาว ≥ 12 ตัวอักษร

**ไม่ดักคำกว้าง** (`ขอ` 422 ครั้ง · `แจ้ง` 294 · `สั่ง` 216 · `ทำ` 162) เพราะติด
"ขอบคุณ/แจ้งรหัส/สั่งซื้อ" จนท่วมจอแล้วคนเลิกใช้ — ผลจริงได้ผู้ต้องสงสัย 249 จาก 4,758 (5.2%)

## ผลที่ตามมา

- **บวก** — งานที่สั่งผ่านไลน์มีที่อยู่ ตรวจสอบย้อนหลังได้ว่าอะไรยังไม่ทำ
- **บวก** — รหัสประตูคลังไม่เคยเข้าระบบ ต่อให้ anon key หลุดก็ไม่มีอะไรให้อ่าน (ตารางปิดสองชั้น)
- **บวก** — ปรับรายการคำได้โดยไม่ต้องแก้ DB (สถานะเก็บแยกจากเกณฑ์ที่ใช้ตัดสิน)
- **ลบ** — ดักคำพลาดได้ทั้งสองทาง งานที่เขียนแบบไม่มีคำเหล่านี้จะไม่ถูกชู
  (ยอมรับไว้ก่อน ถ้าพลาดเยอะค่อยขยับไปใช้ AI อ่าน ซึ่งต่อยอดได้เพราะเก็บดิบไว้แล้ว)
- **ลบ** — ข้อความก่อนวันเปิด webhook ต้องนำเข้าด้วยมือจากไฟล์ export ไม่มีทางดึงอัตโนมัติ
- **ความเสี่ยง** — ตัวกรองรหัสเป็น regex ที่เขียนไว้ **2 ที่คนละภาษา**
  ([lineChatImport.js](../../src/lib/lineChatImport.js) กับ [line-webhook/index.ts](../../supabase/functions/line-webhook/index.ts))
  แชร์ไฟล์กันไม่ได้เพราะคนละ runtime → **แก้ที่หนึ่งต้องแก้อีกที่เสมอ**
- **งานที่ตามมา** — ยังไม่มี due date / มอบหมายงาน / แจ้งเตือนกลับเข้าไลน์

## ทางเลือกที่พิจารณา

- **ให้ client อ่านตารางตรงเหมือนตารางอื่น** — ตัดทิ้ง แชทงานอ่อนไหวกว่าข้อมูลคลังทุกตาราง
  และ ADR-0016 บันทึกไว้แล้วว่า anon key เข้าถึงได้เต็มสิทธิ์ (มีตาราง `temperature_log`
  ที่ RLS ปิดสนิทเป็นตัวอย่างว่าพลาดได้จริง)
- **ให้ AI อ่านแล้วชี้ว่าอันไหนเป็นงาน** — ยังไม่ทำตอนนี้ มีค่าใช้จ่ายต่อข้อความ และต้องส่ง
  บทสนทนาออกนอกระบบ เก็บดิบไว้แล้วต่อยอดทีหลังได้โดยไม่ต้องรื้อ
- **กลบเฉพาะตัวเลขรหัส ไม่ตัดทั้งแถว** — ตัดทิ้ง ข้อความรอบๆ บอกบริบทการเปลี่ยนรหัสอยู่ดี
- **ใช้บอทประกาศรอบเบิก-รับ (Kao-Bot-Chanel)** — ตัดทิ้ง webhook ของ OA นั้นชี้ Apps Script
  ที่ยังทำงานจริง (`doPost` รันทุกครั้งที่มีข้อความ) ทับแล้วพัง; OA "คลังยา" ชี้ `line-groupid-probe`
  ซึ่งถูกลบไปแล้ว = ซาก 404 ทับได้ปลอดภัย (ตรวจใน LINE Console 2026-09-04)
