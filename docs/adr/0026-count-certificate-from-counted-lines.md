# 0026. ใบรับรองผลตรวจนับ — ออกจาก "บรรทัดที่นับแล้ว" ระหว่างรอบยังไม่ปิดได้

- **Status:** Accepted
- **Date:** 2026-09-21

## Context

หัวหน้าคลังต้องการกระดาษที่เซ็นรับรองได้ว่า "ได้ตรวจนับรายการเหล่านี้ไปแล้ว" เก็บเข้าแฟ้มเป็นหลักฐาน

[[รอบตรวจนับประจำปี (Annual Count)]] สร้างบรรทัดรอไว้ครบทุก lot ตั้งแต่เปิดรอบ (629 บรรทัด) แล้วเจ้าหน้าที่ไล่นับตามชั้นวางข้ามวัน — รอบที่เปิดอยู่ ณ วันตัดสินใจนี้นับไปแล้ว 22 จาก 629 และจะกินเวลาอีกหลายสัปดาห์กว่าจะปิด. บรรทัดที่ยังไม่ได้นับมี `counted_qty` ว่าง ซึ่งตาม CONTEXT.md คือ *ยังไม่ได้ตรวจ* ไม่ใช่ผลการตรวจ

แรงกดดัน 2 ทางที่ขัดกัน:

- เอกสารที่มีลายเซ็นรับรอง ต้องไม่กล่าวอ้างเกินกว่าที่ทำจริง — ระบบมีกฎนี้อยู่แล้ว (ADR-0008 เพิ่มเติม 2026-07-16: ห้ามอ้าง "ตรงทั้งหมด" เมื่อมีมิติที่ไม่ได้ตรวจ) เพราะเคยมีบั๊กที่ UI อ้างเกินจริงมาก่อน
- ถ้ารอให้รอบปิดก่อนจึงพิมพ์ได้ กว่าจะได้กระดาษแผ่นแรกคือหลายสัปดาห์ และงานนับที่ทำไปแล้วจะไม่มีหลักฐานระหว่างทางเลย

เพิ่มเติม: ข้อมูลจริงพบว่า [[การสุ่มตรวจนับ (Spot Check / Cycle Count)]] 3 รอบที่ปิดไปแล้วตั้งแต่ ก.ค. ก็มีบรรทัด `counted_qty` ว่างค้างอยู่ 6 แถว (ยุคก่อนกฎ validate 16/07/2569) — ปัญหานี้จึงไม่จำกัดอยู่แค่รอบประจำปี

## Decision

ใบรับรองผลตรวจนับ **ออกจากบรรทัดที่ "นับแล้ว" (มี `counted_qty`) เท่านั้น** และ **พิมพ์ได้แม้รอบยังไม่ปิด**

- เกณฑ์เข้าใบ = มี `counted_qty` — ไม่ใช่ "ตรวจครบ 4 มิติ"; บรรทัดที่ตรวจไม่ครบมิติยังขึ้นใบ แต่ตารางมีคอลัมน์ **"มิติที่ตรวจ" (เช่น `4/4`, `3/4`)** บอกความจริงรายบรรทัด
- **หัวกระดาษระบุสถานะรอบเสมอ** — รอบยังไม่ปิดขึ้นว่า "บันทึกผลตรวจนับ (รอบยังไม่ปิด — นับแล้ว N จาก M รายการ)"; ปิดรอบแล้วจึงเป็น "ใบรับรองผลการตรวจนับ (รอบสมบูรณ์)"
- **ใบล็อกที่ "นับแล้ว" เสมอ ไม่ตามตัวกรองบนจอ** — ต่างจาก Excel ที่ออกตามสิ่งที่ตารางแสดง (Critical Rule #6)
- เลขที่เอกสาร **`SC-<session id>`** พิมพ์จากระบบ ไม่เว้นให้เขียนมือ
- เป็น **เอกสารภายในคลัง** ลายเซ็น 2 ช่อง (เจ้าหน้าที่คลัง + หัวหน้าคลัง) **ไม่อ้างระเบียบพัสดุฯ** บนกระดาษ
- **ไม่แตะข้อมูลเก่า** — 6 แถวตกค้างในรอบ ก.ค. แก้ที่ชั้นแสดงผลอย่างเดียว

## Consequences

- Positive: หลักฐานออกได้ระหว่างงานนับที่กินเวลาหลายสัปดาห์ ตรงกับวิธีทำงานจริงที่เดินนับเป็นชั้นๆ
- Positive: กระดาษไม่กล่าวเกินจริง — ทั้งสัดส่วนที่นับแล้วและมิติที่ตรวจปรากฏบนใบ
- Positive: ข้อมูลเดิมไม่ถูกแตะ ร่องรอย "ตั้งใจนับแต่ไม่ได้นับ" ของรอบเก่ายังสืบค้นได้ (ตรงหลัก append-only ADR-0008)
- Negative / trade-off: ใบไม่ unique ต่อรอบ — พิมพ์ระหว่างนับหลายครั้งได้ แฟ้มจะมีใบเซ็นที่เนื้อหาคาบเกี่ยวกัน ต้องอาศัย "พิมพ์เมื่อ <วันเวลา>" บนกระดาษแยกว่าใบไหนใหม่กว่า
- Negative / trade-off: ใบกับ Excel ให้จำนวนแถวไม่เท่ากันได้ (ใบล็อกที่นับแล้ว, Excel ตามจอ) — เป็นข้อยกเว้นที่ตั้งใจจาก Critical Rule #6 ชดเชยด้วยการระบุสัดส่วนบนหัวกระดาษ
- Follow-ups / risks: ยังไม่ได้ยืนยันว่าจะใช้เป็นหลักฐาน **ตรวจสอบพัสดุประจำปี** ตามระเบียบพัสดุฯ ได้หรือไม่ — ระเบียบกำหนดให้ผู้ตรวจสอบเป็นผู้ได้รับแต่งตั้งที่ไม่ใช่เจ้าหน้าที่พัสดุผู้ดูแลของนั้น ขณะที่ผู้นับปัจจุบันคือเจ้าหน้าที่คลังเอง. `docs/invs-warehouse-reference.md` ยังไม่มีหัวข้อนี้. ถ้าภายหลังต้องใช้ตามระเบียบ ต้องเพิ่มช่องเซ็นที่สาม (`sig-2` → `sig-3`) และทบทวนว่าใครเป็นผู้นับ

## Alternatives considered

- **ออกใบเฉพาะตอนปิดรอบ (certificate แท้)** — สะอาดกว่าในแง่เอกสาร 1 รอบ = 1 ใบ แต่รอบประจำปีกินเวลาหลายสัปดาห์ งานที่นับไปแล้วจะไม่มีหลักฐานระหว่างทาง และทดสอบฟีเจอร์กับรอบเดียวที่มีอยู่ไม่ได้เลย
- **เกณฑ์เข้าใบ = ตรวจครบ 4 มิติ** — เข้มกว่า แต่ขัด CONTEXT.md ที่ระบุว่า lot/exp/ที่เก็บ เป็นมิติเสริมข้ามได้ และจะตัดบรรทัดที่นับจริงแล้วออกจากหลักฐาน (เคสจริง: 2 บรรทัดที่ขาดเฉพาะ `counted_lot`)
- **ลบ/แก้ 6 แถวตกค้างให้ข้อมูลสะอาด** — ขัดหลัก append-only และทำลาย snapshot `system_qty` ณ วันนั้นที่ย้อนสร้างใหม่ไม่ได้
- **ใบออกครบทุกบรรทัดรวมที่ยังไม่นับ** — ตรง Critical Rule #6 ตรงตัวที่สุด แต่เท่ากับให้หัวหน้าเซ็นรับรองของที่ยังไม่มีใครนับ
