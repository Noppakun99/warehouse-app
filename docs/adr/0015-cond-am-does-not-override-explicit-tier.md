# ADR-0015: "เงื่อนไขแตกต่างกัน" (col 27) ไม่ override tier ที่ระบุชัด

## สถานะ
Accepted — 2026-07-30

## บริบท

ADR-0014 เพิ่ม `swap_condition_am` (col 27 จาก Auto-Match) เป็น flag ระดับ**บริษัท** ที่คลังจัดหมวดให้ มี 3 ค่า:
- `เงื่อนไขเดียวกันทุกรายการ` (1,246 แถว)
- `⚠️ ไม่มีข้อมูลเงื่อนไข` (1,190 แถว)
- `เงื่อนไขแตกต่างกัน แล้วแต่รายการ` (150 แถว)

ตอน implement (commit `2865d51`) ตั้งกฎว่า `แตกต่างกัน` → **ข้ามไม่เตือนเลย** ด้วยเหตุผลว่า "นโยบายรายยา เชื่อ tier รวมไม่ได้" (ADR-0012: คืนผิดเจ้าอันตรายกว่าเตือนขาด)

**ตอนตัดสินใจยังไม่มีข้อมูลจริงให้ดู** — `swap_condition_am` ว่าง 100% จนกระทั่ง import `รับ.csv` (30/07/2569) กฎนี้จึงไม่เคยทำงานจริงเลย

### ปัญหาที่พบหลังมีข้อมูลจริง

`cond_am` ถูกเช็ค **ก่อน** อ่าน `tier_detail` ทั้งใน `fetchSwapReturnDue` (db.js) และ `expiry-alert/index.ts` → 150 แถวถูก `continue` ทิ้งก่อนถึง parser ทั้งที่ 118 แถวในนั้นมี tier ที่ระบุชัดเจน:

| tier_detail | แถว | parseReturnPolicyV2 | ควรเตือน? |
|---|---|---|---|
| `รับเปลี่ยนเมื่อหมดอายุ ตามจำนวนจริง` | 113 | `after_exp` | ✅ ใช่ |
| `แลกเปลี่ยนได้ก่อนหมดอายุ 3 เดือน` | 5 | `before_exp` | ✅ ใช่ |
| `ไม่รับแลกเปลี่ยนคืน` / `ยาขายขาด` ฯลฯ | 32 | `binary`/`receive_threshold` | ❌ ไม่ (no_return อยู่แล้ว) |

= **false negative** — 118 แถวถูกตัดออกก่อนถึง parser ทั้งที่มี tier ชัด

**ขนาดผลกระทบจริง (วัดแล้ว ไม่ใช่ประมาณ):** จำนวนที่ถูกบล็อก ≠ จำนวนที่จะเตือน — ต้องดูสถานะที่ V2 คืนด้วย. ทดสอบด้วย `exp` อีก ~2.5 เดือน:

| tier | แถว | V2 status | เตือนไหม |
|---|---|---|---|
| `รับเปลี่ยนเมื่อหมดอายุ ตามจำนวนจริง` | 113 | `ok` | ยังไม่ถึงกำหนด |
| `แลกเปลี่ยนได้ก่อนหมดอายุ 3 เดือน` | 5 | `overdue` | ✅ เตือน |
| `ไม่รับแลกเปลี่ยนคืน` ฯลฯ | 32 | `no_return` | ไม่เตือน (ถูกแล้ว) |

**ที่เตือนเพิ่มทันที = 5 แถว** ส่วน 113 แถว `after_exp` จะกลายเป็น `due/overdue` **เมื่อใกล้/เลย exp** — คือของที่จะพลาดในอนาคตถ้าไม่แก้ ไม่ใช่ของที่พลาดอยู่ตอนนี้ทั้งหมด

(บันทึกไว้กันเข้าใจผิดซ้ำ: ตัวเลข "118 แถวหายจาก email" ที่เคยรายงานตอนแรก **สูงเกินจริง** เพราะนับเฉพาะการถูก `continue` ไม่ได้ trace ต่อว่าผลลัพธ์สุดท้ายคือ alert หรือไม่)

### ข้อมูลที่ปลดล็อกการตัดสินใจ

`cond_am` ผูกกับ **บริษัท** ไม่ใช่ lot — ภิญโญฟาร์มาซี 118 แถว/21 ยา แต่มี `tier_detail` แค่ **2 แบบ** distinct

แปลว่า flag นี้บอกว่า *"บริษัทนี้ให้เงื่อนไขไม่เท่ากันทุกรายการ"* — ซึ่งเป็นเหตุผลให้ไม่เชื่อ**นโยบายรวมของบริษัท** (V1 free-text) แต่**ไม่ใช่เหตุผลให้ทิ้ง tier ราย lot** ที่คลังแจกแจงมาให้แล้ว

## การตัดสินใจ

**`cond_am = แตกต่างกัน` override เฉพาะเมื่อ lot นั้น *ไม่มี* tier ที่ระบุชัด**

ลำดับใหม่ (ทั้ง 4 จุดที่ต้อง sync ตาม Critical Rule #11):

```
1. lot มี tier_detail ที่ parse ได้ชัด (shape ≠ ambiguous)
      → ใช้ V2 ตาม tier  ← cond_am ไม่มีผล
2. lot ไม่มี tier / tier กำกวม (ambiguous)
      → ถ้า cond_am = แตกต่างกัน  → review (ไม่เดา ไม่เตือน)
      → ไม่งั้น fallback V1 (นโยบายบริษัท)
```

**เหตุผล:** `tier_detail` เป็นข้อมูล**ราย lot ที่เจาะจงกว่า** และเป็นสิ่งที่คลังแปลง free-text → structured ให้เองแล้ว ส่วน `cond_am` เป็น flag **ระดับบริษัท** ที่หยาบกว่า — ข้อมูลที่เจาะจงกว่าควรชนะ (specific overrides general)

ADR-0012 "คืนผิดเจ้าอันตรายกว่าเตือนขาด" **ยังใช้อยู่** แต่ใช้กับกรณี *lot ชนหลายบริษัท* (`supplierByLot = null`) ซึ่งเป็นคนละเรื่อง — กรณีนั้นไม่รู้ว่าคืนใคร ส่วนกรณีนี้รู้บริษัทแน่ชัด แค่บริษัทมีหลายเงื่อนไข

## ผลกระทบ

- **150 แถวเข้าสู่ V2 แทนที่จะถูกทิ้ง** — สถานะจริงมาจาก tier ไม่ใช่ถูกตัดตั้งแต่ต้น
- เตือนเพิ่ม **ทันที 5 แถว** (`before_exp` ที่ overdue แล้ว)
- **113 แถวจะเตือนเมื่อถึงกำหนด** (`after_exp` — คืนได้หลัง exp) นี่คือค่าหลักของการแก้: ก่อนหน้านี้จะไม่มีวันเตือนเลยแม้เลย exp ไปแล้ว
- 32 แถว `binary`/`receive_threshold` ยังไม่เตือน (V2 คืน `no_return` เอง) — ผลลัพธ์ไม่เปลี่ยน แต่ตอนนี้มาจากการตัดสินของ tier ไม่ใช่การ skip แบบเหมารวม
- ต้อง sync **4 ที่** ตาม Critical Rule #11: `swapPolicy.js` · `fetchSwapReturnDue` (db.js) · `App.jsx buildReturnInfo` · `expiry-alert/index.ts` (+ redeploy)

## ทางเลือกที่ปฏิเสธ

- **คงกฎเดิม (skip ทั้งหมด)** — ปลอดภัยเกินจนพลาดของจริง 118 แถว; และขัดกับเจตนาของ ADR-0014 ที่ import tier มาเพื่อให้แม่นขึ้น
- **ลบการเช็ค `cond_am` ทิ้งทั้งหมด** — เสี่ยงเกิน: lot ที่ไม่มี tier จะกลับไปเชื่อนโยบายบริษัทรวมทั้งที่บริษัทบอกเองว่าเงื่อนไขไม่เท่ากัน
- **ให้ `cond_am` แค่เปลี่ยน badge ไม่บล็อก** — ครึ่งๆ กลางๆ: ยังเตือนผิดสำหรับ lot ที่ไม่มี tier
