# 0031. รายงาน 5 แฟ้ม (แฟ้ม 4 DISTRIBUTION · 5 INVENTORY) ออกจากทะเบียนคงคลังรายเดือน + ตารางผูก TPU ราย รหัส+บริษัท

- **Status:** Accepted — 16/11/2569 (user เลือกแบบ (ก))
- **Date:** 2026-11-16
- **เกี่ยวข้อง:** [ADR-0007](0007-monthly-stock-ledger.md) (ทะเบียนคงคลังรายเดือน) · [ADR-0027](0027-excel-is-source-of-truth-for-inventory-and-dispense.md) (Excel เป็นตัวจริง) · CONTEXT §รายงาน 5 แฟ้ม · §TPU ของยา · §หีบห่อในรายงาน

## Context

รพ. ต้องส่ง DMSIC ทุกเดือนภายใน 10 วันหลังสิ้นเดือน คลังรับผิดชอบแฟ้ม 4 (ยอดจ่ายรายกลุ่มหน่วยเบิก) และแฟ้ม 5 (คงคลังราย lot) รอบ เม.ย.–ส.ค.69 ทำมือใน Excel แล้วพบข้อผิดพลาดซ้ำ: วันที่ยอดคงคลังไม่ตรงสิ้นเดือน · ชื่อการค้าไม่มีความแรง/รูปแบบ · BASE_UNIT เป็นคำไทย · DIS_DEPT_GROUP เป็น `3` ทุกแถว · บริษัทเดียวมีเลขภาษีหลายเลข · DISTRIBUTION พ.ค.–ต.ค.69 ยังไม่ได้ส่ง

ข้อมูลที่ต้องใช้กระจายอยู่ 3 ที่: ยอดสิ้นเดือน + บริษัท + exp อยู่ในชีท snapshot `Master_<เดือน>` · ยอดจ่ายรายหน่วยงานอยู่ใน `dispense_logs` (ชีทเบิก · ไม่มีบริษัท) · TPU/ชื่อการค้า/เลขภาษีไม่มีในระบบเลย (อยู่บนบิล · ไฟล์ที่เคยส่ง · `TPU_GPUID.xlsx` ที่ user ลงเอง)

## Decision

1. **ยอดคงคลังมาจาก `stock_ledger` เท่านั้น** — CLI `scripts/import-ledger.mjs` อ่านชีท `Master_<เดือน>` (โครงคอลัมน์เดียวกับ Master — ใช้ `mapMasterRow` ของ `ledgerSeed.js` ตัวเดิม) เขียนเป็นงวดสถานะ `closed` ทันที เพราะ snapshot มีได้ต่อเมื่อปิดยอดเดือนนั้นแล้ว · งวดที่ `closed` อยู่แล้วนำเข้าทับได้เฉพาะเมื่อระบุเหตุผล (ลง audit)
   - **ไม่ใช้ `closeLedgerPeriod`** — ฟังก์ชันนั้นคำนวณ closing ใหม่ด้วย `computeClosing` (AC + AA − Z + Y) ซึ่งผิดกับแถวบริจาค/โครงการที่ seed เอา closing จาก AD/AJ แต่ carry-in จาก AC
   - เพิ่มคอลัมน์ `exp` · `pack_size` (AQ) · `sub_unit` (AR) ใน `stock_ledger` — แฟ้ม 5 บังคับ EXPIRE_DATE · PACK_SIZE · BASE_UNIT
2. **ยอดจ่าย (แฟ้ม 4) = `dispense_logs` ของเดือนนั้น** จับคู่กับแถว ledger ของงวดเดียวกันด้วย `รหัส + lot + ชนิดรายการ + ราคา` (cost-layer key) เพื่อเอาบริษัท/หน่วย/packsize · ตัดแถวตามนิยาม CONTEXT §แฟ้มจ่าย (หมดอายุ · คืนยา · แลกเปลี่ยนคืน · บันทึกเท่านั้น · เบิกเพิ่มจากความผิดพลาด) · หน่วยงาน → กลุ่ม 1–4 ที่ฟังก์ชันเดียวใน `src/lib/dmsicReport.js`
3. **ตาราง `drug_tpu_map`** unique `(drug_code, company)` เก็บ TPUID · ชื่อการค้า · คำหน่วย DispUnit · แหล่งที่มา — รหัสเดียวเปลี่ยนบริษัท = แถวใหม่ (CONTEXT §TPU ของยา) · **ตาราง `vendor_tax_id`** 1 บริษัท = 1 เลข · seed ครั้งแรกจาก `TPU_GPUID.xlsx` + ไฟล์ที่เคยส่ง + ดัชนีบิล ผ่าน CSV ให้ user ตรวจก่อนนำเข้า · ยาที่ขาด TPU อ่านจากรูปบิลเฉพาะคู่ที่ขาด
4. **ประกอบรายงานใน pure module** `src/lib/dmsicReport.js` (golden test) — คืน `{ rows, problems }` · **มีปัญหาที่สเปกห้ามว่าง (ไม่มี exp/lot/BASE_UNIT/เลขภาษี · หน่วยงานไม่รู้กลุ่ม · ยอดเป็นทศนิยมในฟิลด์ INTEGER) = แสดงรายการให้แก้ ไม่เดาแทน** · TPU ไม่พบ = `99` + ชื่อยา Master ตาม CONTEXT แต่ยังนับเป็นข้อสังเกตให้เห็นจำนวน
5. **ออกรายงานจากโมดอลในหน้าทะเบียนคงคลัง** — เมนูทะเบียนคงคลังเปิดให้ `staff` + `admin` (เดิม admin เท่านั้น) · ปุ่มนำเข้า/ปิด/เปิดงวดยังจำกัด admin ภายในหน้าเหมือนเดิม · หัวหน้า/พี่โบว์ให้สิทธิ์รายคนผ่าน "สิทธิ์ระบบ" · ไฟล์ออกเป็น .xlsx ทุกฟิลด์รหัส/วันที่เป็น Text ตามสเปก

## Consequences

- ทุกเดือนหลังปิดยอดต้องรัน `import-ledger.mjs --sheet Master_<เดือน>` ก่อนออกรายงาน (เพิ่มเป็นขั้นในสกิลปิดเดือน)
- ส่งย้อนหลังได้เฉพาะเดือนที่ยังมีชีท snapshot (ตอนนี้ในไฟล์มี ก.ย.69 · ต.ค.69 · เดือนเก่ากว่าย้ายไฟล์ไปแล้ว ต้องระบุ `--file`)
- รายงานถูกเท่าที่ตาราง TPU ครบ — คู่ รหัส+บริษัท ใหม่ทุกครั้งที่บริษัทเปลี่ยน ต้องเติม (ดัชนีบิลจด TPU ตั้งแต่ 16/11/2569)
- แฟ้ม 3 RECEIPT ยังไม่อยู่ในขอบเขต (คลังรับผิดชอบแค่ 4/5)

## Alternatives considered

- **(ข) CLI อ่าน Excel ออก xlsx ตรง ไม่มีปุ่มในแอป** — เร็วกว่า แต่หัวหน้า/พี่โบว์ออกเองไม่ได้ และยอดย้อนหลังขึ้นกับว่าชีท snapshot ยังอยู่ไหม
- **ผูก TPU ที่รหัสยาอย่างเดียว** — ผิดเมื่อบริษัทเปลี่ยน (1520048 มี 2 TPU)
- **ส่งแถว `เบิกเพิ่มจากความผิดพลาด` หักลบเข้าหน่วยงานเดิม** — หมายเหตุเป็นข้อความอิสระ ผูกหน่วยงานเดิมไม่ได้ และส่วนใหญ่เป็นการปรับยอดนับ (user เลือกตัดทั้งหมด)
