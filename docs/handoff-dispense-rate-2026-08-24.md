### 🔴 B1 — ชีทวิเคราะห์บวกแพ็คคนละขนาดเป็นตัวเลขเดียว
`1610010 Fenofibrate 200mg` มิ.ย.69: ชีทลง **94** = (85 กล่อง 30เม็ด) + (9 กล่อง 300เม็ด) บวกดิบ
แปลงถูกต้อง = 5,250 เม็ด ÷ 300 = **17.5** → เพี้ยน **5.4 เท่า**

ผลลาม: Avg/เดือน 35.0 (ควร 9.5) → SS 69 → ROP 95 > คงเหลือ 65 → **"สั่งเพิ่ม" 123 หน่วย = 67,650 บาท**
ถ้าเรทถูก ROP ≈ 24 < 65 → **ไม่ต้องสั่ง**

ขอบเขต: 32 รหัสเคยเปลี่ยนแพ็ค → 68 ช่องที่แยกออก = **ไม่แปลง 33 / แปลง 32 / อื่น 3** (สูตรเดียว 3 พฤติกรรม)
สแกนเต็มหน้าต่างเรท (มิ.ย.–ส.ค.69) แล้ว → **กระทบจริง 1 รหัสเดียวคือ 1610010**
(1660083 / 1670057 ที่โผล่มาด้วย เป็น artifact — master `หน่วย` ว่าง ไม่มีเป้าให้แปลง ตัดทิ้งแล้ว)

### 🔴 B2 — `qty_base` ในชีทเบิกผิดตั้งแต่ต้นทาง
`qty_base = ปริมาณออก × packsize` โดย packsize เป็นแพ็ค **ปัจจุบัน** แต่คูณกับแถว **ประวัติ**
หลักฐาน: `08/06/2026 ออก 30 กล่อง 30เม็ด → packsize=300 → qty_base=9,000` ความจริง **900 ผิด 10 เท่า**
→ **ห้าม port สูตรนี้เข้าแอป** (ผู้ใช้เคยถามว่าจะเติมคอลัมน์นี้ลง export ไหม — นี่คือคำตอบ)
ถ้าจะทำ ต้องใช้ `qty_out × factor(drug_unit ของแถวนั้น)`

### 🟠 B3 — 2 คอลัมน์ชื่อ "3 เดือนล่าสุด" ครอบคนละช่วง
`Avg/เดือน (3 ด.ล่าสุด)` = มิ.ย.+ก.ค.+ส.ค.69 · `รวมเบิก3เดือนล่าสุด` = พ.ค.+มิ.ย.+ก.ค.69 (ช้า 1 เดือน)

### 🟠 B4 — ตัวคูณ SS = 2 ทุกรหัส ไม่แยก VEN
451/451 ใช้ ×2 (V=61, E=282, N=108) ขณะที่ `CLAUDE.md` Rule #13 ระบุ V2.0/E1.5/N1.0
→ แอปจะให้ SS ต่ำกว่าชีท 25% (E) และ 50% (N) รวม **390 รหัส**
**ต้องถามคลังว่าอันไหนคือของจริง ก่อนแก้ข้างใดข้างหนึ่ง**

### 🟠 B5 — หน้าต่างเรทประกาศไว้ 3 ที่ เป็น 3 ค่า
banner ชีท = "5 เดือน" · หัวคอลัมน์ = "3 ด." · `CONTEXT.md` §เรท = "4 เดือน (ธ.ค.–มี.ค.)"

### 🟡 B6 — ROP ปิดวงไม่ได้ 221/451 รหัส

- Windows/Git Bash: เขียนไฟล์ผลลัพธ์ด้วย path **relative** แล้วค่อย `cat` (absolute path แบบ `/c/...` ใน python ล้มบ่อย) และ stdout ภาษาไทยพังบ่อย → เขียนลงไฟล์แล้ว `cat` ปลอดภัยกว่า
