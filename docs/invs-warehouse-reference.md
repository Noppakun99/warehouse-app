> **นี่ไม่ใช่ระบบของเรา** — INVS คือโปรแกรมจัดซื้อและบริหารคลังเวชภัณฑ์ที่กระทรวงสาธารณสุขแจกฟรี ใช้อยู่ 295 รพ. เราศึกษาไว้เพื่อ **ยืมกระบวนการที่ราชการยอมรับแล้ว** มาปรับใช้ ไม่ใช่เพื่อลอกทั้งระบบ

> ศึกษาเมื่อ 2026-08-24 จากคู่มือฉบับ ก.พ. 2563 · ผลการเทียบกับแอปเราและลำดับงานอยู่ใน [handoff-invs-2026-08-24.md](handoff-invs-2026-08-24.md)

## 1. INVS คืออะไร

- โปรแกรม desktop (client–server) พัฒนาที่ **รพ.สรรพสิทธิประสงค์** ต่อยอดจาก INV DOS · ฐานข้อมูล MS-SQL / MySQL / MariaDB
- สนับสนุนโดย สป.สธ. · ศูนย์ข้อมูลข่าวสารด้านเวชภัณฑ์ · ชมรมเภสัชกรโรงพยาบาล
- ครอบคลุม: บันทึกสัญญา → ตรวจสอบแผนซื้อ → สั่งซื้อ → รับเข้าคลัง → เบิกจ่าย → **คลังใหญ่-คลังย่อย** → เชื่อมข้อมูลกับโปรแกรมพัสดุ → ตัดจ่ายจากห้องยา → รายงาน (ผู้ใช้เขียน SQL ออกแบบรายงานเองได้)
- มีโมดูลข้างเคียง: `sMigrate` (โอนจาก INV DOS/Excel), `sDispense` (ดึงยอดจ่ายจาก HOSxP/HOMC), `INVS2X` (ส่งข้อมูลเข้า Express), INVS for Web / Mobile, Telegram Notify

**เหตุผลที่ใช้เป็นแบบอ้างอิง:** กระบวนการของมันถูกออกแบบให้สอดคล้องกับระเบียบพัสดุและการส่งข้อมูลกระทรวง — ของที่ตรวจสอบได้อยู่แล้ว

## 3. กระบวนการ "ระบบคลัง" (คู่มือหน้า 60–93)

### คลังใหญ่

**① รับจากขนส่ง** (หน้า 60–61)
บันทึกพัสดุที่ขนส่งมาถึง *ก่อน* การรับเข้าคลังอย่างเป็นทางการ — วันที่รับขนส่ง · เลขที่ใบส่ง · น้ำหนักขนส่ง · จำนวนทั้งหมด · ค่าขนส่ง · หมายเหตุ → ได้ **เลขที่รับขนส่ง** ไว้อ้างต่อในขั้นรับเข้าคลัง

**② จ่ายด่วน + ปลดเปลื้อง** (หน้า 62–63) — *"ของออกก่อน เอกสารตามหลัง"*
- ฟอร์มจ่ายด่วนมีแค่ **คลัง + รายการ + จำนวน — ไม่มีช่องเอกสารใดๆ** (ไม่มี PO / เลขบิล / กรรมการตรวจรับ)
- ผลคือ *"จำนวนคงคลังจะเพิ่มขึ้นตามจำนวนที่บันทึกจ่ายด่วน"* — ตั้งยอดชั่วคราวให้จ่ายออกได้โดยไม่ติดลบ
- **ปลดเปลื้อง** = บันทึกรับเข้าคลังจริงโดย **ระบุ Lot no. + วันหมดอายุให้ตรงกับรายการจ่ายด่วน** → กดยืนยันแล้วโปรแกรมเด้งเตือนว่ามีจ่ายด่วนค้าง → ไปล้างที่เมนู **โอน → แผนโอน → จ่าย**
- คำว่า "กรรมการตรวจรับ / หนังสือตรวจรับ" **ไม่ปรากฏในขั้นนี้เลย** — โผล่เฉพาะขั้นรับเข้าคลัง

**③ รับเข้าคลัง** (หน้า 65–74) — 3 กรณี
1. *มีการบันทึกสั่งซื้อแล้ว* — กรอกเลขใบสั่งซื้อ ข้อมูลเด้งอัตโนมัติ · **จำนวนส่งไม่ครบให้ระบุจำนวนรับใหม่** (เกิดค้างรับ)
2. *มีบันทึกรับจากขนส่งแล้ว* — กรอกเลขรับขนส่ง ข้อมูลเด้งอัตโนมัติ
3. *ไม่ได้บันทึกสั่งซื้อ* — กรอกเองทั้งชุด: เลขที่ใบสั่งซื้อ · วันที่ · วิธีจัดซื้อ · เลขโครงการ · ผู้จำหน่าย · ประเภทงบประมาณ · รูปแบบการสั่งซื้อ · GFMIS **+ เลขที่บิล · เลขที่รับขนส่ง · หนังสือตรวจรับ · รายชื่อกรรมการตรวจรับ · เลขที่ใบรับ · วันที่ใบรับ · วันที่ใบแจ้งหนี้ · วันที่ส่งการเงิน**

ระดับรายการเก็บ: จำนวนรับ · ขนาดบรรจุ · ราคา/pack · Lot no. · วันหมดอายุ · **สถานที่เก็บ** · **ประเภท (ซื้อ / แถม / บริจาค)** · บริษัทผู้ผลิต (จำค่าล่าสุดให้) · **บาร์โค้ดระดับหีบห่อ**

**④ ยืนยันการจ่าย** (หน้า 75–77)
คลังใหญ่ค้นใบขอเบิกตามช่วงวันที่/หน่วยที่จ่ายไป · เลือก "เฉพาะที่ยังไม่ยืนยัน" · **มี pop-up + เสียงเตือนเมื่อมีใบเบิกใหม่** · แก้จำนวนจ่ายรายรายการได้ · ยกเลิกรายรายการ/ทั้งใบได้ · พิมพ์ใบสั่งรายการเวชภัณฑ์

### คลังย่อย *(ไม่มีในบริบทของเรา — รพ. นี้มีคลังเดียว)*

**⑤ ขอเบิก** (หน้า 78–83) — แบบทั่วไป / **แบบเลือก Lot no.** / แก้ไขใบ · หน่วยเป็น **pack**, เบิกไม่เต็ม pack พิมพ์ตัวเลขตามด้วย `*` (เช่น `500*`) · มีปุ่ม **เบิกด่วน**
**⑥ จ่ายออก** (หน้า 84–85) — คลังย่อยบันทึกการใช้จริงทุกครั้ง *"เพื่อเก็บประวัติการใช้และเป็นข้อมูลสำหรับการประมวลอัตราการใช้สำหรับขอเบิกกับคลังใหญ่ต่อไป"*
**⑦ รับคืน** (หน้า 86–87) — เลือกหน่วยงาน · วันที่ · **สาเหตุการคืน** · การดำเนินการ · **จำนวนคืนทั้งหมด แยกจาก จำนวนยาดี** · Lot/EXP/ที่เก็บ · ประเภท (ยาซื้อ/ยาฟรี) · กดยืนยันรับ
**⑧ โอน + ปลดเปลื้อง** (หน้า 87–91) — โอนระหว่างคลัง (ยิงบาร์โค้ดได้) · **ทะเบียนค้างจ่าย (รอปลดเปลื้อง) พิมพ์ได้ + ส่งออก Excel** · ทยอยจ่ายทีหลังรายรายการ

## 5. ชุดรายงานมาตรฐาน 32 ตัว + สถานะฝั่งเรา

จากหน้ารายงานของ รพ. ตัวอย่าง (`hosp_id=00001`) — ถือเป็น "สิ่งที่งานคลัง รพ.รัฐ ถูกคาดหวังให้ผลิตได้"

**เรามีแล้ว** — ยาใกล้หมดอายุ · รายงานการรับเวชภัณฑ์ (+ ตามบริษัท / ตามใบส่ง / export Excel) · สรุปการเบิกจำแนกตามหน่วยเบิก · อัตราคงคลังประจำเดือน (บางส่วน — StockLedger) · มูลค่ารับ-จ่าย 30 ลำดับแรก (บางส่วน) · สรุปภาพรวมงานคลัง (Dashboard)

**ยังไม่มี** — อัตราคงคลังแยกตามรายการยา · **รายการยาที่ไม่มีการจ่ายออกจากคลัง (dead stock)** · **จำนวนคงคลังตามวันที่ (ย้อนหลัง)** · สรุปภาระงาน (ต่อคน) · สรุปการจ่าย/รับ ตามบัญชียา รพ. (ED/NED) · มูลค่าจำแนกตามกลุ่มยา / กลุ่มเภสัชวิทยา / กลุ่มยาย่อย · รับเข้าคลังตามวิธี/รูปแบบการจัดซื้อ · รายงานรับ-จ่ายพัสดุตามระเบียบ · สรุปงานบริหารคลังตามปีงบ · สรุปจ่ายยาคลังภายนอก · รายงานการออกใบสั่งซื้อ · รายการยาค้างจ่าย · รายงานค้างรับจากการสั่งซื้อ · ส่งข้อมูลนวัตกรรมไทย

## 6. INV DataSet — ชุดข้อมูลส่งกระทรวง

ร่างสำหรับงานประชุมเภสัชกรผู้รับผิดชอบงานคลัง (update ก.พ. 2559) — **4 แฟ้ม**

| แฟ้ม | ฟิลด์สำคัญ |
|---|---|
| **DRUGLIST** | HOSP_CODE · WORKING_CODE · GENERIC_NAME · TRADE_NAME · **TMTID (TPU)** · **NCD24** · **NLEM** (`E`/`N` = ในบัญชียาหลักหรือไม่) · **PRODUCT_CAT** (1 ซื้อตามท้องตลาด / 2 รพ.ผลิตเอง / 3 สมุนไพรซื้อ / 4 สมุนไพร รพ.ผลิต / 5 อื่นๆ) · CONTENT_VALUE + CONTENT_UNIT + BASE_UNIT · STATUS · D_UPDATE · PERIOD_REPORT |
| **PURCHASE** | + MANUFAC_NAME · VENDOR_NAME · QTY_RCV · PACK_SIZE · UNIT_COST (ราคา/pack) · **DISCOUNT** |
| **INVENTORY** | + **QTY_ONHAND** · PACK_SIZE · UNIT_COST · **VALUE_ONHAND** · **LOT_NO** · **EXPIRE_DATE** (YYYYMMDD ค.ศ.) |
| **DISTRIBUTE** | + QTY_DIS · BASE_UNIT · TOTAL_VALUE · **DIS_DEPT** (`1` OPD+ER · `2` IPD+WARD · `3` รพ.สต. · `4` อื่นๆ) |

**สถานะของเรา:** `INVENTORY` ทำได้เกือบครบวันนี้ (ขาด TMT/NCD24) · `DISTRIBUTE` ขาดแค่ `DIS_DEPT` ซึ่งจะได้จากงานโครงสร้างหน่วยงาน · `DRUGLIST` ต้องเติม NLEM/PRODUCT_CAT/TMT/NCD24 ก่อน · `PURCHASE` ต้องมีระบบจัดซื้อ (นอกขอบเขต)
คอลัมน์ `tpu_code` / `gpu_code` / `ttmp_code` **มีอยู่แล้วใน `receive_logs` แต่ว่างเปล่า 100%** — schema พร้อม เหลือเติมข้อมูล

## 7. ระเบียบพัสดุที่กำกับกระบวนการนี้

ระเบียบกระทรวงการคลังว่าด้วยการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. 2560 — การตรวจรับอยู่ **หมวด 6 ข้อ 175–189** (พ.ร.บ. หมวด 10 มาตรา 100–105)

- ลำดับ: ผู้ขายส่งมอบ → เจ้าหน้าที่พัสดุ **ลงทะเบียนรับหนังสือส่งมอบ/ใบวางบิล + ตรวจความครบถ้วนของเอกสาร** → **ส่งเอกสารให้คณะกรรมการตรวจรับ** → ตรวจรับ → **ออกใบตรวจรับพัสดุอย่างน้อย 2 ฉบับ** → รายงานผล → เบิกจ่ายเงิน
- คณะกรรมการตรวจรับ **อย่างน้อย 3 คน** เว้นแต่วงเงิน **ไม่เกิน 100,000 บาท** ตั้งบุคคลเดียวเป็นผู้ตรวจรับได้
- แหล่งสรุประบุกรอบเวลาตรวจรับพัสดุทั่วไป **ภายใน 3 วันทำการนับแต่วันส่งมอบ**
- **พัสดุที่ยังไม่ผ่านการตรวจรับ เบิกจ่ายไม่ได้** — ใบตรวจรับเป็นเงื่อนไขของการเบิกจ่ายเงิน
- เอาของมาใช้ก่อนของจริงเข้า → ช่องทางที่ถูกคือ **การยืม ข้อ 207–208**: หลักฐานเป็นลายลักษณ์อักษร + เหตุผล + กำหนดวันส่งคืน + อนุมัติโดยหัวหน้าหน่วยงาน

**นัยต่อ "จ่ายด่วน" ของเรา:** INVS ไม่บังคับเอกสาร แต่ระเบียบบังคับ → ถ้าเราทำฟีเจอร์นี้ ต้องบังคับอ้างฐานเอกสาร 1 ใน 2 (เลขที่รับขนส่ง/บิล **หรือ** เลขที่ใบยืม) และห้ามให้บิลที่มีจ่ายด่วนค้างเดินไปถึงขั้นตั้งหนี้โดยไม่ผ่านการตรวจรับ

## 8. สิ่งที่เราเลือกรับ / ไม่รับ

**รับมาปรับใช้** — รับจากขนส่ง · จ่ายด่วน+ปลดเปลื้อง (เพิ่มการบังคับเอกสารตามระเบียบ) · ค้างจ่าย/รอปลดเปลื้อง · ประเภทรายการรับ ซื้อ/แถม/บริจาค · หน่วยงานมีรหัส+ประเภท+สถานที่ตั้ง · เอกสารตรวจรับ (หนังสือ+กรรมการ) · เบิกเลือก Lot เป็น option + flag เบิกด่วน · กรอบบัญชีต่อหน่วยเบิก · master ยาตามสเปก DataSet

**ไม่รับ (นอกขอบเขต "งานคลัง")** — แผนจัดซื้อปี · บันทึกสัญญา · ใบสั่งซื้อ · ค้างรับจากการสั่งซื้อ · งบประมาณ/GFMIS · แฟ้ม PURCHASE

**ไม่รับ (ไม่มีในบริบทนี้)** — คลังย่อย · จ่ายออกของคลังย่อย · โอนระหว่างคลัง — เพราะ รพ. นี้มีคลังเดียว ทุกหน่วยงานเบิกตรงจากคลังยา
> ผลข้างเคียงที่ต้องรู้: INVS ใช้ "จ่ายออกของคลังย่อย" ป้อนกลับเป็น *อัตราการใช้จริง* เมื่อเราไม่มีขั้นนั้น อัตราการใช้ของเรา = **ยอดที่คลังจ่ายออกไป** (ซึ่ง ReorderApp ใช้อยู่แล้วและถูกต้องสำหรับคลังเดียว) แต่ช่วงที่หน่วยงานตุนของ ตัวเลขความต้องการจะสูงกว่าความจริงชั่วคราว

**เรามีดีกว่า INVS อยู่แล้ว ไม่ต้องถอย** — กระดิ่งแจ้งเตือน realtime · ตรวจนับ append-only + snapshot · บังคับ checklist+รูปตอนตรวจรับ · นโยบายเปลี่ยน/คืนบริษัทรายบริษัท · อุณหภูมิตู้เย็นพร้อม provenance · สแกนบิล AI + alias ชื่อยา
