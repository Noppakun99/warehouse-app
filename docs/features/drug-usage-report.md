- เมนู `reorder` เปิดหน้านี้ · ของเดิมทั้งหมด (ตาราง ROP · ใบสั่งซื้อแยกบริษัท · แจ้งซื้อแล้ว · เทียบ Excel · Verification · History) อยู่ใต้ปุ่ม **"โหมดละเอียด"** ไม่ลบ

## ตัวเลข (Rule #6)

- คงเหลือ / หน่วยหลัก / เรท / คงอยู่ได้อีก = `buildDrugProfile` ตัวเดียวกับบัตรยา → ตรงบัตรยาโดยโครงสร้าง
- **`usageBaseQty` = กฎเดียวกับ `fetchMonthlyDispenseUsage`** (db.js เรียกตัวนี้แล้ว) — ตัดแถวไม่ใช่การใช้ตาม CONTEXT §เรท + ×factor ของหน่วยแต่ละแถวก่อนรวม (dispense_logs รหัสเดียวลงหลายหน่วยปน: Para มี `1000เม็ด`/`500เม็ด`/`เม็ด` — บวกดิบได้ 10,017 แทน 27)
- รายหน่วยงานจับกลุ่มด้วย `normDept` ("ห้องยา G" = "ห้องยาG") · น้อยสุดเท่ากันหลายหน่วยงานได้ (แสดงทุกตัว)
- รับเข้า: ตารางแสดงราย lot · นับ "ครั้ง"/"รับล่าสุด" เป็น**รายบิล** (`groupReceiptBills` key วันรับ+เลขบิล+บริษัท — Rule #19) · บิลที่หน่วยฐานไม่ตรงหน่วยหลัก (450ml vs ขวด) แปลงไม่ได้ → แสดงหน่วยดิบ และยอดรวมรับเข้าเป็น "-"
- แจ้งซื้อ: `pendingRequestFor` (ป้ายเดียวกับบัตรยา/ตารางวิเคราะห์) · ไม่มีค้าง → บอกครั้งล่าสุด (มาส่งแล้ว/ยกเลิก) จาก `requestState`
- ตรวจกับข้อมูลจริง 14/11/2569 Para 1000227 (พ.ย.68–ต.ค.69): เบิก 345 กล่อง 74 ครั้ง 11 หน่วยงาน · ห้องยาG 275 · เรท 32 (ก.ค.–ต.ค.) — mockup เดิม 356.05/78/34.75 เพราะนับ `บันทึกเท่านั้น` ต.ค. (ER-ออกหน่วย 1,000 เม็ด + ปฐมภูมิ 10,000 เม็ด) ซึ่งนิยามเรทไม่นับ
