## ลำดับงานคลัง (ห้องยาG)

ทุกขั้นที่แตะ `.xlsm` อยู่ใต้ `/excel-com` (สำเนา scratchpad → diff → วางกลับ) · ลงชีทเบิกใช้กฎ `/dispense-entry`

1. **copy** `ยอดคลังยา_69.xlsm` ไป scratchpad (ห้ามเปิดไฟล์ใน OneDrive)
2. **แผน**: `node scripts/online-req.mjs --plan --file <สำเนา> --out plan.json [--date YYYY-MM-DD]`
   ดึงใบ `pending` + `sheet_entered_at IS NULL` ของห้องยาG → เลือก lot ต่อรายการ → เลข บย. ถัดไปจาก `_ทะเบียนใบเบิก.csv` → ไม่เขียนอะไร
   ⚠ ถ้าแผนมี `[วันแจ้งสั่งซื้อ?]` (ยาหมด–ต้องใส่วันแจ้งสั่ง) ต้องเติมใน plan.json ก่อน ตัวเขียนชีทปฏิเสธ
3. **เขียนชีทบนสำเนา**: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\online-req-write.ps1 -StockPath <สำเนา> -PlanPath plan.json -LogPath log.txt`
   ตรวจแถวท้าย + คีย์/ราคา/U ของแถว Master → เขียน B–Q, W/X, AD → `Calculate` → แช่ค่า R–V → ตรวจ T/U ของแถวในแผนลดตาม Σq → Save สำเนา (ไม่ผ่าน = ไม่ Save) · อ่านผลจาก log (console PS 5.1 แสดงไทยเพี้ยน)
4. **diff ทีละเซลล์** กับสำเนาเดิม (`/excel-com` ขั้น 7–8) — **ตรวจด้วยว่าไม่มีแถว Master นอกแผนที่ T เปลี่ยน** (ดูกับดักข้อ 1)
5. **writeback dry-run**: `node scripts/online-req.mjs --writeback --plan plan.json` — ตรวจทุกใบว่ายัง `pending` · ยังไม่ลงชีท · `updated_at` ตรงแผน (ผู้เบิกแก้จำนวน/เพิ่มยาเข้าใบ — RPC `requester_edit_requisition` ตั้ง `updated_at` ทุกครั้ง · ถอน หรือเจ้าหน้าที่กดจัดจ่ายเองหลังทำแผน = ไม่เขียนใบไหนเลย) → **รันก่อนวางไฟล์กลับ**ใช้เป็นด่านได้
6. วางสำเนากลับ (`cmp` ก่อน/หลัง) → PDF ใบเบิก + ทะเบียน + คิวพิมพ์ ตาม `/dispense-entry`
7. **writeback `--commit`** → `receipt_no` · `sheet_entered_at` · `status = approved` · `picked_allocation` ต่อรายการ · audit `sheet_enter_requisition`
8. **`import:master` หลังข้อ 7 เสมอ** — ยอดจองเลิกหักเมื่อ "ลงชีทแล้ว + นำเข้าหลังลงชีท" (`reservation.js`) · นำเข้าก่อน writeback = ใบยังหักยอดซ้ำกับยอดที่ชีทลดแล้ว

**ใบรอลงชีททุกหน่วยงาน**: `node scripts/online-req.mjs --pending [--json]` (อ่านอย่างเดียว · `sheet_entered_at` ว่าง · ไม่นับ rejected/cancelled · ตั้งแต่ 13/11/2569) — `check-complete.py` ข้อ 14 เรียกทุกครั้ง (user สั่ง 23/11/2569) · ห้าม `process.exit()` หลัง query ในโหมดนี้: Node 24 บน Windows ล้ม `UV_HANDLE_CLOSING` exit 127 ทำให้ check-complete อ่านผลไม่ได้

**หน่วยงานนอก pilot**: `--plan --req REQ-…,REQ-…` วางแผนเฉพาะใบที่ระบุ (ทุกหน่วยงาน · ใบต้อง pending + ยังไม่ลงชีท ไม่งั้นหยุด) แล้วทำข้อ 3–8 เหมือนห้องยาG — ใช้ครั้งแรก 23/11/2569 ห้องยา 1 (REQ-20261120-6883 → บย.70/0092 40 แถว · REQ-20261123-9871 → บย.70/0093) · ⚠ หมายเหตุ `lot X หมด · คงคลังรวม N (lot …)` ยังนับ lot ที่ใบเดียวกันจ่ายหมดไปแล้วด้วย (Warfarin) ตรวจก่อนเขียน

**ติ๊กจัด/จ่ายในแอปหลังพิมพ์ใบ (user สั่ง 23/11/2569)**: `check-complete.py` ข้อ 15 (`online-req.mjs --undispensed --json`) จับใบที่ลงชีทแล้ว + PDF ในคิวพิมพ์ติ๊ก "พิมพ์แล้ว" แต่ในแอปยังขั้นรอจัด/รอตรวจจ่าย → **ถาม user ว่าจัด/จ่ายออกเสร็จหรือยัง** (ห้ามติ๊กเองจากการเดา) · user ยืนยันแล้ว → `online-req.mjs --mark-picked --req …` (จัดเสร็จ) หรือ `--mark-dispensed` (จัด+ตรวจแล้วจ่ายออก) `[--commit]` — ใช้ `pickPayload` + `startPickingRequisition`/`verifyAndDispenseRequisition` ตัวเดียวกับปุ่มในแอป (audit/กระดิ่งเหมือนกดเอง) · ชื่อผู้จัด/ผู้ตรวจค่าเริ่มต้น `Noppakun Chaykuntod` (`--name` เปลี่ยนได้) · ใบยังไม่ลงชีท = หยุด ให้จัดในแอป

ใบที่ลงชีทมือ (นอก pilot): `node scripts/online-req.mjs --mark-entered --req REQ-… --receipt บย.70/xxxx [--commit]` ตั้งแค่ `receipt_no` + `sheet_entered_at` ไม่แตะสถานะ/lot · ไม่ตั้ง = ใบหักยอดจองค้างตลอดไป

## เตือนแบ่งจ่ายตามเรท + Lead Time (`dispenseCheck.js` — 24/11/2569)

แอปตรวจใบด้วยเกณฑ์เดียวกับ `.claude/skills/dispense-entry/scripts/rate_check.py` (ลำดับเดิม: ของไม่พอ → ใช้ไม่ทันก่อน exp lot แรก = จ่ายตามขอ → ใบเดียวกินของมาก ≥1 เดือนของเรทหรือ ≥ครึ่งของที่จ่ายได้ → หลังจ่ายพอใช้ไม่ถึง LT)
- **ยอดแนะนำแบ่งจ่าย** = `floor(จ่ายได้ − Avg/วัน × LT)` = จ่ายได้เท่าที่หลังจ่ายยังเหลือพอให้ทั้ง รพ. ใช้ระหว่างรอของรอบใหม่ (user ตัดสิน 24/11/2569)
- **ผู้เบิก (ตะกร้า `CartView`)**: กล่องเหลือง "คลังอาจแบ่งจ่าย แนะนำไม่เกิน N…" เฉพาะเมื่อหลังจ่ายไม่ถึง LT **และไม่มีของกำลังมา** (รอตรวจรับ/แจ้งซื้อรอของ) — **ไม่บล็อกปุ่มส่ง** ส่งเต็มจำนวนได้ คลังตัดสินอีกที · คงเหลือ 0 ใช้ข้อความ "ยาหมดในคลัง" เดิม · ข้อความนี้แทนบรรทัด "เกินคงเหลือ…คลังจ่ายเท่าที่มี" ของรายการเดียวกัน (ไม่ให้สองข้อความขัดกัน)
- **คลัง (`RequisitionDetail`)**: บรรทัดใต้ชื่อยา (แดง = ต้องตัดสิน · เหลือง = มีของกำลังมา จ่ายตามขอได้) + ตัวกรอง "ควรพิจารณาแบ่งจ่าย" · คำนวณสดจากจำนวนอนุมัติที่แก้ → ลดเหลือยอดแนะนำแล้วป้ายหายเอง · **เฉพาะใบที่ยังไม่ลงชีท** (ลงชีท+นำเข้าแล้ว inventory ตัดยอดใบนี้ไปแล้ว คิดซ้ำจะขึ้นของไม่พอปลอม) · จ่ายได้ = lot ใน `loadStaffLots` ลบ lot รอตรวจรับ
- **ข้อมูล** `fetchDispenseCheckData(codes)` (db.js อ่านอย่างเดียว กรองเฉพาะรหัสในใบ ~1.4 วิ): เรท 4 เดือนที่ปิดงวด (กฎบัตรยา) · **LT = เฉลี่ย leadtime บิลซื้อ** (ADR-0001 · ไม่มีบิล = 20) — ตรงคอลัมน์ "Lead Time (วัน) [avg]" ของชีทวิเคราะห์ทั้ง 15 รหัสที่เทียบ 24/11 · ห้ามใช้ `drug_reorder_config.lead_time_days` (เป็น 15 ทุกแถวเพราะตัวนำเข้าไม่รู้จักหัวคอลัมน์นี้) · รอตรวจรับ = `inventory.receive_status` · แจ้งซื้อ = `pendingRequestFor`
- **ต่างจาก rate_check โดยตั้งใจ**: เรทแอป 4 เดือน vs ชีท 3 เดือน (CONTEXT §เรท) → ยอดแนะนำคลาดกันได้เล็กน้อย · ไม่มีธง exp < 7 เดือน (หน้าคลังมีตัวกรองใกล้หมดอายุอยู่แล้ว) · `online-req.mjs --plan` ยังไม่ใช้โมดูลนี้ (Claude ใช้ rate_check ต่อ)
