# ใบเบิกออนไลน์ → ชีทเบิก (เบิกยาออนไลน์ เฟส 1)

นิยามคำ (ใบเบิกออนไลน์ · ใบจ่ายก่อนลงชีท · ตัดยอดชั่วคราว · หน่วยคีย์ · ลัง) อยู่ [CONTEXT.md §Requisition](../../CONTEXT.md) — ไฟล์นี้เก็บ**วิธีทำงานของโค้ด/สคริปต์**เท่านั้น
การส่งใบพร้อมกัน + ยอดจอง → [ADR-0028](../adr/0028-requisition-submit-concurrency.md) · กฎเลิกหักยอดจอง → `src/lib/reservation.js`

## ขอบเขตตอนนี้ (pilot 13/11/2569)

- ลงชีทด้วยสคริปต์เฉพาะ **ห้องยาG** (`PILOT_DEPT` ใน [onlineReqPlan.js](../../src/lib/onlineReqPlan.js)) · หน่วยงานอื่นลงชีทมือแล้วใช้ `--mark-entered`
- ผู้เบิกคีย์เป็น**หน่วยซื้อ** (กล่อง/ขวด/ถุง × packsize) แอปเก็บ `requested_qty` เป็นหน่วยย่อยสุดเหมือนเดิม (ADR-0004)
- 1 ใบ = ประเภทเดียว (`req_type` saline/supply/drug — `src/lib/reqType.js`)

## ลำดับงานคลัง (ห้องยาG)

ทุกขั้นที่แตะ `.xlsm` อยู่ใต้ `/excel-com` (สำเนา scratchpad → diff → วางกลับ) · ลงชีทเบิกใช้กฎ `/dispense-entry`

1. **copy** `ยอดคลังยา_69.xlsm` ไป scratchpad (ห้ามเปิดไฟล์ใน OneDrive)
2. **แผน**: `node scripts/online-req.mjs --plan --file <สำเนา> --out plan.json [--date YYYY-MM-DD]`
   ดึงใบ `pending` + `sheet_entered_at IS NULL` ของห้องยาG → เลือก lot ต่อรายการ → เลข บย. ถัดไปจาก `_ทะเบียนใบเบิก.csv` → ไม่เขียนอะไร
   ⚠ ถ้าแผนมี `[วันแจ้งสั่งซื้อ?]` (ยาหมด–ต้องใส่วันแจ้งสั่ง) ต้องเติมใน plan.json ก่อน ตัวเขียนชีทปฏิเสธ
3. **เขียนชีทบนสำเนา**: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\online-req-write.ps1 -StockPath <สำเนา> -PlanPath plan.json -LogPath log.txt`
   ตรวจแถวท้าย + คีย์/ราคา/U ของแถว Master → เขียน B–Q, W/X, AD → `Calculate` → แช่ค่า R–V → ตรวจ T/U ของแถวในแผนลดตาม Σq → Save สำเนา (ไม่ผ่าน = ไม่ Save) · อ่านผลจาก log (console PS 5.1 แสดงไทยเพี้ยน)
4. **diff ทีละเซลล์** กับสำเนาเดิม (`/excel-com` ขั้น 7–8) — **ตรวจด้วยว่าไม่มีแถว Master นอกแผนที่ T เปลี่ยน** (ดูกับดักข้อ 1)
5. **writeback dry-run**: `node scripts/online-req.mjs --writeback --plan plan.json` — ตรวจทุกใบว่ายัง `pending` · ยังไม่ลงชีท · `updated_at` ตรงแผน (ผู้เบิกแก้/ถอน หรือเจ้าหน้าที่กดจัดจ่ายเองหลังทำแผน = ไม่เขียนใบไหนเลย) → **รันก่อนวางไฟล์กลับ**ใช้เป็นด่านได้
6. วางสำเนากลับ (`cmp` ก่อน/หลัง) → PDF ใบเบิก + ทะเบียน + คิวพิมพ์ ตาม `/dispense-entry`
7. **writeback `--commit`** → `receipt_no` · `sheet_entered_at` · `status = approved` · `picked_allocation` ต่อรายการ · audit `sheet_enter_requisition`
8. **`import:master` หลังข้อ 7 เสมอ** — ยอดจองเลิกหักเมื่อ "ลงชีทแล้ว + นำเข้าหลังลงชีท" (`reservation.js`) · นำเข้าก่อน writeback = ใบยังหักยอดซ้ำกับยอดที่ชีทลดแล้ว

ใบที่ลงชีทมือ (นอก pilot): `node scripts/online-req.mjs --mark-entered --req REQ-… --receipt บย.70/xxxx [--commit]` ตั้งแค่ `receipt_no` + `sheet_entered_at` ไม่แตะสถานะ/lot · ไม่ตั้ง = ใบหักยอดจองค้างตลอดไป

## กฎเลือก lot (`planRequisition`)

อยู่หัวไฟล์ [onlineReqPlan.js](../../src/lib/onlineReqPlan.js) — สรุป: 1 แถวเบิก = 1 แถว Master (lot + ราคา + ชนิดรายการ) · ลำดับ `sortLotsForDispense` (ยาซื้อ exp ≤6 เดือน → ยาสนับสนุน → FEFO, exp เท่ากัน = รับก่อนจ่ายก่อน) · ข้ามแถวรอตรวจรับ/หมดอายุ/U ≤ 0 · ของไม่พอ = จ่ายเท่าที่มี + W/X + หมายเหตุ · exp ในหมายเหตุ = **ค.ศ.** `วว/ดด/ปปปป` (user เลือก 13/11/2569) · หลายใบในแผนเดียวกันใช้ยอดหลังใบก่อน (pool ลดตามลำดับ)

## ฝั่งแอป — ใบห้องยาG ที่รอลงชีท (commit `f38a561`)

`awaitsSheetEntry(req)` = `pending` + ยังไม่มี `sheet_entered_at` + หน่วยงาน = `PILOT_DEPT` — ใบเหล่านี้เป็นคิวของสคริปต์ จึงใน `RequisitionApp`:
- ป้าย **"รอลงชีทเบิก"** ในรายการใบ
- **ซ่อน "อนุมัติด่วน" และอนุมัติหลายใบ** (เลือกหลายใบแล้วใบเหล่านี้ไม่ถูกนับ)
- หน้ารายละเอียดเหลือปุ่ม **"จัดจ่ายเอง (ก่อนลงชีท)"** + `ConfirmModal` = ทางสำรอง[ใบจ่ายก่อนลงชีท](../../CONTEXT.md) (user เลือกให้คงไว้ 13/11/2569) · audit `update_requisition` + `details.action_detail = 'approve_before_sheet'` · กดแล้ว `updated_at` เปลี่ยน → writeback ของแผนเก่าปฏิเสธใบนั้น (ข้อ 5)

## กับดักที่รู้

1. **แถว Master คีย์ซ้ำ (รหัส + lot + ราคา + ชนิดรายการ) = T นับซ้ำ** — สูตร T เป็น `SUMIFS` ชีทเบิกด้วยคีย์นี้ แถวเบิก 1 แถวจึงลด U ของ**ทุกแถว**ที่คีย์ตรง (ทดลอง 13/11: จ่าย NSS 5ml lot 2F065017 จาก M408 10 หลอด → M409 ที่ไม่อยู่ในแผน U 20→10, AB −1,000 · มูลค่าเบิกเกินจริง 1,000 บาท) · **ด่านของ ps1 ไม่จับ** (ตรวจเฉพาะแถวในแผน) และแถว "✅ ถูกต้อง" ท้าย Master ก็ไม่จับ (สมการยังสมดุล) → ต้องแยกชนิดรายการ (`ซื้อยา(2)`) ก่อนลงชีท · สแกน 13/11 เจอ 3 คู่ ทั้งหมดมาจากบิล IV6960441 (1460152 M207/208 · 1590012 M379/380 · 1440401 M408/409) — **แก้แล้ว 13/11/2569** (แถวบิลใหม่เป็น `ซื้อยา(2)` · สูตร S/AA/Y/Z/AB รองรับ `(2)` เหมือนเดิม ยอดรับเข้า/มูลค่าไม่เปลี่ยน) · **ตัวเช็คเร็ว: Master คอลัมน์ AP ขึ้น `ซ้ำ`** (COUNTIFS รหัส+lot+ชนิดรายการ — ไม่ดูราคา จึงอาจขึ้นกับคู่ที่ราคาต่างกันซึ่ง T ไม่นับซ้ำ เช่น 1690065 M1062/1063)
2. แผนผูกกับสำเนา ณ ตอนทำแผน (แถวท้ายชีทเบิก `expectLast` + เลข บย. จาก `_ทะเบียนใบเบิก.csv`) — ลงใบมือแทรกระหว่างทำแผนกับเขียน ps1 ปฏิเสธเพราะแถวท้ายไม่ตรง → copy ใหม่แล้วทำแผนใหม่ (อย่าแก้เลขใน plan.json เอง)
3. `--writeback --plan` เคยตกสาขา `--plan` (แก้ใน `f38a561`) — สาขา `--plan` ต้องเช็ค `!A.has('--writeback')`
