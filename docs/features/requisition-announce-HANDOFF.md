# บอทประกาศรอบเบิก-รับ เข้ากลุ่ม LINE — สรุปสำหรับอธิบายต่อ

> งานที่ทำ 14–15 ส.ค. 2026 · เอกสารนี้ใช้เล่าให้หัวหน้า/เพื่อนร่วมงาน/ผู้ดูแลระบบคนถัดไปฟัง
> รายละเอียดเชิงเทคนิคอยู่ใน [requisition-announce.md](./requisition-announce.md)

---

## 1. ปัญหาเดิมคืออะไร

กลุ่ม LINE ของ ward มีบอทเก่า (Google Apps Script ชื่อ `KaoBot`) คอยประกาศว่าวันไหนส่งใบเบิก
วันไหนมารับของ แต่มีปัญหา 3 อย่าง:

| ปัญหา | ผลกระทบกับ ward |
|---|---|
| **ไม่รู้จักวันหยุดราชการ** | ประกาศให้มารับของในวันที่คลังปิด คนมาเก้อ |
| **`@All` ไม่เด้งเตือน** | บอทเก่าพิมพ์ตัวอักษร `@All` เฉยๆ ไม่ใช่ mention จริง คนไม่ได้รับแจ้งเตือน |
| **เงียบหายท้ายเดือน** | โควตา LINE หมดแล้วหยุดส่งเงียบๆ ไม่มีใครรู้ว่าทำไมไม่มีประกาศ |

## 2. แก้อย่างไร

ย้ายบอทมาอยู่ในระบบคลังยา (Supabase) แทน Apps Script โดยเพิ่ม 3 ส่วน:

```
ทุกวัน 09:00 น.
   ↓
pg_cron (ตัวตั้งเวลาในฐานข้อมูล) เรียกโปรแกรม
   ↓
Edge Function "requisition-announce"
   ├─ อ่านปฏิทินวันหยุดจากตาราง public_holiday
   ├─ ตัดสินเองว่า "วันนี้ต้องประกาศไหม และประกาศว่าอะไร"
   ├─ เช็คโควตา LINE ก่อนส่ง
   └─ ส่งเข้ากลุ่มพร้อม mention @All ทั้งกลุ่ม
```

**จุดสำคัญ**: cron ยิงทุกวันก็จริง แต่**โปรแกรมเป็นคนตัดสินเองว่าวันไหนส่ง**
ทำแบบนี้เพราะวันประกาศ**เลื่อนได้ตามวันหยุด** ถ้าล็อกเวลาไว้แค่ จันทร์/พุธ
พอเจอวันหยุดแล้วรอบเลื่อนไปอังคาร จะไม่มีใครยิงเลย

## 3. ประกาศอะไรบ้าง (4 วัน/สัปดาห์)

| วัน | ประกาศ | ข้อความ |
|---|---|---|
| จันทร์ | วันส่งใบเบิก | "ฝ่ายไหนจะเบิก ส่งใบเบิกมาได้เลย" + บอกว่ารับพรุ่งนี้ |
| อังคาร | วันมารับของ | "วันนี้มารับของได้ 9.00-15.00น." |
| พุธ | วันส่งใบเบิก | เหมือนจันทร์ |
| พฤหัส | วันมารับของ | เหมือนอังคาร |

**ความสามารถที่บอทเก่าไม่มี:**
- วันหยุดราชการ → ไม่ประกาศ และเลื่อนรอบให้อัตโนมัติ พร้อม**บอกเหตุผล**
  (เช่น "13 ต.ค. เป็นวันหยุด (วันคล้ายวันสวรรคต ร.9) วันมารับของจึงเลื่อนไป 14 ต.ค.")
- หยุดยาว 4 วันขึ้นไป → เตือน "รอบนี้เป็นรอบสุดท้ายก่อนหยุด กรุณาเบิกเผื่อ"
- วันหยุดติดกันจนรอบชนกัน → ยุบเหลือรอบเดียว ไม่ประกาศซ้ำ

## 4. เรื่องโควตา LINE — ต้องเข้าใจตรงกัน

LINE ให้โควตาฟรี **300 ข้อความ/เดือน** และการส่งเข้ากลุ่ม **นับรายหัว**
กลุ่มมี 24 คน → ส่ง 1 ครั้ง = **หัก 24 ข้อความ** → เดือนหนึ่งส่งได้แค่ **12 ครั้ง**

ประกาศ 4 วัน/สัปดาห์ = ~17 ครั้ง/เดือน = **เกินโควตา**

**การตัดสินใจ (15 ส.ค. 2026)**: เลือกครบ 4 วัน โดย**ยอมรับว่าจะเงียบช่วงท้ายเดือน**

ต่างจากบอทเก่าตรงที่ **ระบบเตือนเจ้าหน้าที่คลังล่วงหน้าก่อนเงียบ** — เตือนใน**กระดิ่งแจ้งเตือนของแอปคลังยา**
(ไม่ส่งเข้ากลุ่ม LINE เพราะเรื่องโควตาเป็นงานหลังบ้าน ward รู้ไปก็ทำอะไรไม่ได้):

- เหลือส่งได้ ≤ 2 ครั้ง → "โควตาแจ้งเตือน LINE ใกล้หมด — ส่งประกาศเข้ากลุ่มได้อีก N ครั้ง"
- ครั้งสุดท้าย → "ส่งประกาศครั้งสุดท้ายของเดือนแล้ว"
- วันที่ประกาศไม่ออก → "ประกาศรอบเบิก-รับวันนี้ไม่ได้ส่งเข้ากลุ่ม จะกลับมาต้นเดือนหน้า"

**ward เห็นแค่ประกาศปกติเสมอ** ไม่เห็นเรื่องโควตาเลย

**ถ้าอยากได้ครบทุกวันไม่ขาด** = ต้องอัปเกรดแพ็กเกจ LINE (เสียเงิน)
การส่งแบบไม่ mention ก็ยังนับรายหัวเท่าเดิม ไม่ช่วยประหยัด

## 5. ปฏิทินวันหยุด — ใครต้องดูแล

หน้า **ควบคุมระบบ → ปฏิทินวันหยุด** (admin เท่านั้น)

⚠️ **แหล่งความจริงคือคนกรอก ไม่ใช่สูตรคำนวณ** เพราะวันหยุดพุทธศาสนาเลื่อนตามจันทรคติ
และ ครม. ประกาศวันหยุดพิเศษเพิ่มกลางปีได้

⚠️ **ปฏิทินว่าง = ระบบถือว่าไม่มีวันหยุด** (ไม่ใช่ "ไม่มีข้อมูล") → จะประกาศทับวันหยุดจริง

**งานที่ต้องทำก่อนกลางเดือน ธ.ค. 2569**: กรอกวันหยุดปี 2570
เพราะรอบพุธ 30 ธ.ค. ต้องคำนวณวันรับเป็นต้นเดือน ม.ค. ถ้าระบบไม่รู้ว่า 1 ม.ค. หยุด จะประกาศผิด

## 6. ขั้นตอนที่ทำไปแล้ว (สำหรับคนที่ต้องทำซ้ำ/แก้ต่อ)

| # | ขั้น | ใครทำได้ |
|---|---|---|
| 1 | เขียน logic ปฏิทินรอบ + golden test 116 ข้อ | dev |
| 2 | Deploy Edge Function | dev (ผ่าน Supabase MCP หรือ CLI) |
| 3 | ตั้ง secrets: `LINE_REQ_CHANNEL_TOKEN`, `LINE_REQ_GROUP_ID` | **ต้องกดใน Dashboard เอง** |
| 4 | หา group id ของกลุ่ม | ตั้ง webhook ชั่วคราว → พิมพ์ในกลุ่ม → อ่าน log → **คืน webhook เดิม** |
| 5 | ทดสอบส่งจริงในกลุ่มทดสอบก่อน | ยืนยันว่า `@All` เด้ง noti จริง |
| 6 | ติดตั้ง `pg_net` + สร้าง vault secrets + ตั้ง cron | dev |
| 7 | ปิดบอทเก่า (ลบ trigger ใน Apps Script) | **ต้องทำก่อนเปิด cron** ไม่งั้นประกาศซ้ำ 2 ตัว |

## 7. กับดักที่เจอจริง — อย่าพลาดซ้ำ

**🛑 ไฟล์ `requisition_announce_cron.sql` เวอร์ชันแรกมีบั๊กที่มองไม่เห็น**
มันอ้าง vault secret ชื่อ `expiry_alert_auth` โดยเข้าใจว่า "ใช้ร่วมกับระบบแจ้งเตือนยาหมดอายุได้"
แต่ความจริง secret นั้น**ไม่มีอยู่จริง** และ `pg_net` ก็**ยังไม่ได้ติดตั้ง**

ถ้ารันตามไฟล์ → cron จะยิงด้วยรหัสผ่านว่าง → ถูกปฏิเสธ (401) **เงียบทุกวัน ไม่มี log ไม่มีใครรู้**
เพราะโปรแกรมไม่เคยถูกเรียก จึงไม่มีแม้แต่ audit log ให้เห็น

**บทเรียน**: ตั้ง cron เสร็จอย่าเชื่อว่าจบ — ต้องทดสอบยิงจริงแล้วดูว่าได้ **200** ไม่ใช่แค่ดูว่ามี job อยู่ในตาราง

**🛑 อย่าแก้ `REQUISITION_WEEKDAYS` เป็น `[1,2,3,4]` เพื่อให้ยิง 4 วัน**
ค่านี้หมายถึง "วันส่งใบเบิก" เท่านั้น ถ้าใส่อังคารเข้าไป ระบบจะคิดว่าอังคารเป็นวันเบิก
แล้วคำนวณวันรับเป็นพุธ ซึ่งผิด — วันรับต้องคำนวณจากวันเบิกเสมอ (ดูโค้ด `kind: 'pickup'`)

**⚠️ ทดสอบด้วย PowerShell ระวัง**: `Invoke-RestMethod` ทำภาษาไทยเพี้ยนจนขึ้น error 500 ปลอม
ทั้งที่โปรแกรมตอบ 200 ปกติ — ต้องใช้ `System.Net.Http.HttpClient` แทน

## 8. ตรวจสอบว่าทำงานปกติไหม

| อยากรู้ว่า | ดูที่ |
|---|---|
| วันนี้ส่งหรือยัง | Audit Log ในระบบคลังยา → action `line_announce` |
| ทำไมไม่ส่ง | Audit Log จะบันทึกเหตุผล (ไม่ใช่วันประกาศ / โควตาไม่พอ) |
| โควตาเหลือเท่าไร | ดูใน audit log ช่อง `quota_remain_before` และ `sends_left_after` |
| ทดสอบโดยไม่ส่งจริง | เรียกโปรแกรมด้วย `{"dryRun": true}` |
| ดูข้อความล่วงหน้า | หน้าปฏิทินวันหยุด มีบล็อก "ตัวอย่างประกาศ 4 สัปดาห์ข้างหน้า" |
