**ประกาศ 2 ครั้ง/สัปดาห์ (จันทร์ + พุธ) ไม่ใช่ 4** — ข้อความเดียวครอบทั้งวันส่งใบเบิกและวันมารับของของรอบนั้น

### ทำไมไม่ประกาศ 4 วันตามที่ขอ

โควตา LINE ของ OA นี้ = **300 ข้อความ/เดือน** (วัดจาก API จริง 2026-08-14) และ push เข้ากลุ่ม **นับรายหัว** กลุ่มมี **24 คน**

| รูปแบบ | ข้อความ/เดือน | ผล |
|---|---|---|
| 4 ประกาศ/สัปดาห์ (บอทเดิม) | ~418 | ❌ เกิน 39% → **เงียบ ~10 วันท้ายเดือนทุกเดือน** |
| 2 ประกาศ/สัปดาห์ (ที่ใช้) | ~209 | ✅ เหลือ headroom 91 |

**หลักฐานว่าบอทเดิมเงียบจริง**: 14 ส.ค. 2026 ใช้ไปแล้ว 193/300 = 8 ประกาศ × 24 คน พอดีกับ 2 สัปดาห์แรก → เหลือ 107 ยิงได้อีก 4 ครั้ง แล้วหมดราว 21 ส.ค.

ถ้าอัปเกรดแพ็กเกจในอนาคต กลับไป 4 วันได้โดยแก้แค่ `REQUISITION_WEEKDAYS` + cron ไม่ต้องรื้อโค้ด

## สถาปัตยกรรม

```
pg_cron (ทุกวัน 09:00 ไทย)
   └→ Edge Function requisition-announce
        ├→ อ่าน public_holiday (service role)
        ├→ announceSchedule.js: วันนี้เป็นวันประกาศไหม + ข้อความว่าอะไร
        ├→ เช็คโควตา LINE (ไม่พอ → ไม่ยิง + บันทึก audit)
        └→ push textV2 + mention all
```

**`supabase/functions/_shared/announceSchedule.js` เป็น plain JS โดยเจตนา** — Deno import ได้ และ node (golden test) ก็ import ได้ (`package.json` เป็น `type: module`) → **logic อยู่ที่เดียว** ไม่ต้อง sync สำเนา TS เหมือน `swapPolicy` ที่ Critical Rule #11 บังคับ sync 4 ที่

## กฎที่ implement แล้ว

1. **วันหยุด → ไม่ประกาศ** และรอบเลื่อนไปวันทำการถัดไป (เลื่อนทั้งวันส่งใบเบิกและวันมารับของ)
2. **วันรับ = วันทำการถัดไปจากวันส่งใบเบิก** — ปฏิทินชุดเดียว วันรับ derive เอา
3. **วันเบิกชนวันรับได้** — วันหนึ่งเป็นทั้งวันรับ (รอบก่อน) และวันเบิก (รอบใหม่) ไม่ถือว่าผิด
4. **หยุดยาว ≥ 4 วันติด (นับ ส-อา ด้วย) → ยุบเหลือรอบเดียว** + เตือน "เบิกเผื่อวันหยุด" ในรอบสุดท้ายก่อนหยุด
5. **เมื่อเลื่อนต้องบอกเหตุผล** — ทั้งกรณีวันเบิกเลื่อน และกรณีวันเบิกไม่เลื่อนแต่วันรับเลื่อน (ไม่อธิบายเสาร์-อาทิตย์ คนรู้อยู่แล้ว)
6. **"พรุ่งนี้" ใช้เฉพาะเมื่อวันรับเป็นวันถัดไปจริง** — เคสประกาศศุกร์/รับจันทร์ ต้องระบุวันตรงๆ

## `@All` ต้องใช้ `textV2` เท่านั้น

```json
{
  "type": "textV2",
  "text": "📋 {everyone} ฝ่ายไหนจะเบิก ...",
  "substitution": { "everyone": { "type": "mention", "mentionee": { "type": "all" } } }
}
```

**ส่ง type `text` แล้วพิมพ์ `@All` ลงไปตรงๆ = ตัวอักษรธรรมดา ไม่มีใครได้ noti** (บอทเดิมเป็นแบบนี้) ข้อจำกัด: ใช้ได้เฉพาะ reply/push และปลายทางต้องเป็น group/multi-person chat — **OpenChat ใช้ไม่ได้** (Messaging API ไม่รองรับ)

`announceSchedule.js` ใส่ `{everyone}` เป็น placeholder ไว้ให้แล้ว และ golden test มี assertion กันไม่ให้ใครเปลี่ยนกลับเป็น `@All`

## ปฏิทินวันหยุด

**แหล่งความจริง = ตารางที่คนกรอก ไม่ใช่สูตรคำนวณ** เพราะ (1) วันหยุดพุทธศาสนาเลื่อนตามจันทรคติ (2) ครม. ประกาศวันหยุดพิเศษเพิ่มกลางปี

หน้า admin: **ควบคุมระบบ → ปฏิทินวันหยุด** (`page: 'holiday'`, admin เท่านั้น)
มีบล็อก **"ตัวอย่างประกาศ 4 สัปดาห์ข้างหน้า"** แสดงข้อความจริงพร้อม badge `เลื่อน`/`ยุบรอบ`/`เตือนก่อนหยุดยาว` — ใช้ตรวจว่ากรอกถูกก่อนของจริงยิง

### กรอกอัตโนมัติจาก Google Calendar

ปฏิทิน `th.th#holiday@group.v.calendar.google.com` แยกประเภทในฟิลด์ `description`:
- `วันหยุดนักขัตฤกษ์` → เอา
- `วันสำคัญ` → **ตัดทิ้ง** (คริสต์มาส/วาเลนไทน์/ตรุษจีน ไม่ใช่วันหยุดราชการ)

⚠️ **รายการนี้ไม่ครบ — ขาดวันหยุดพุทธศาสนา** (มาฆบูชา/วิสาขบูชา/อาสาฬหบูชา/เข้าพรรษา) ใช้เป็น**ร่าง**เท่านั้น ต้องมีคนตรวจเทียบประกาศจริงเสมอ

## ข้อควรระวัง

- **ปฏิทิน 2570 ต้องกรอกก่อนกลางเดือน ธ.ค. 2569** ไม่ใช่รอต้นปี — รอบพุธ 30 ธ.ค. คำนวณวันรับเป็น 1 ม.ค. 2570 (วันขึ้นปีใหม่) เพราะระบบยังไม่รู้ว่าปีหน้าหยุดวันไหน
- **ปฏิทินว่าง = ระบบถือว่าไม่มีวันหยุด** ไม่ใช่ "ไม่มีข้อมูล" → ประกาศทับวันหยุดจริง มี banner เตือนในหน้า admin แต่กันไม่ได้ 100%
- **ต้องปิดบอทเดิมก่อนเปิด cron** ไม่งั้นประกาศซ้ำ 2 ตัว + เผาโควตาคู่
- **เวลาส่ง 09:00 ไทย** — เท่ากับที่บอทเดิมยิง (09:13) และตรงกับเวลาเปิดรับของในตัวข้อความ (9.00-15.00น.)
- **บอทเดิม = Apps Script ฟังก์ชัน `mainAlert` + time-driven trigger ยิงทุกวัน แล้วเช็ควันในสัปดาห์เอง** (โครงสร้างเดียวกับตัวใหม่) — ปิดโดยลบ trigger เท่านั้น โค้ดกับ token ยังอยู่ ถ้าต้องย้อนกลับสร้าง trigger ใหม่ได้ใน 30 วินาที
- **Apps Script ตัวเดิมยังมี Web app deployment ค้างอยู่ (Active, Execute as owner, Who has access: Anyone)** URL ลงท้าย `.../AKfycby_EFGT3E_Eu4uWexgs3o4OWChc0dzLAudxBxQhS6TaggKLHP1921GQl7AxjP-dIJd_4Q/exec` — **ไม่ได้ลบ** เพราะยังไม่รู้ว่ามันทำอะไร (น่าจะเป็น LINE webhook รับข้อความเข้ากลุ่ม) การลบ trigger ไม่กระทบตัวนี้ ถ้ายืนยันได้ว่าไม่มีใครใช้ค่อย archive
- Edge Function รันบน UTC — ใช้ `todayBangkok()` เสมอ ห้าม `new Date()` ตรงๆ (ก่อน 07:00 จะได้วันก่อนหน้า)
